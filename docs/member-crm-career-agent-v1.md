# 会员 CRM 顾问工具 V1

## 上线边界

- 仅在会员 CRM 单会员工作台内使用；
- 首版仅超级管理员可见、可运行和审核；
- 模型固定通过 Qwen 内地兼容接口调用；
- 用户前台简历只读，CRM 简历独立存储；
- 所有生成结果均为内部草稿，不写入 C 端简历、用户画像或匹配缓存；
- 不做自动投递、自动覆盖资料或无人审核的 Agent 行为。

## 首期工作流

```text
选择用户前台或 CRM 简历，并可填写本次分析重点
  -> 选择是否带入 CRM 背景
  -> 本地移除邮箱、电话和链接
  -> 本地结构化提取
  -> Qwen 简历诊断与候选人画像 Skill
  -> Schema 校验
  -> 原文证据逐条校验
  -> 保存待审核成果
  -> 超级管理员校正画像、补充备注并确认/归档
```

相同简历、分析重点、CRM 背景、模型和 Skill 版本产生相同输入指纹，默认复用已完成结果；相同任务并发提交只执行一次。只有“重新生成”会再次调用模型。

## Skill 协议

首期 Skill 为 `resume_diagnosis`，版本由以下三项共同确定：

- workflow version；
- prompt version；
- deterministic parser version。

输出必须包含：

- 摘要和顾问咨询重点；
- 原文证据账本；
- 核心优势；
- 高、中、低优先级简历问题；
- 候选人画像草稿；
- 当前、过渡、长期职业方向；
- 最多六个高价值追问；
- 质量校验结果。

每条证据必须包含简历原文摘录。服务端会做归一化字符串定位，无法定位的证据会被删除；完全没有可信证据时整次生成失败，不保存成果。

## 数据模型

`member_crm_agent_runs` 只保存运行元数据、输入指纹、Skill/模型版本、Token 用量和脱敏错误，不保存原始 Prompt。

`member_crm_agent_artifacts` 保存结构化顾问成果、版本、来源引用、顾问备注和审核状态。首版证据账本作为成果 JSON 的一部分，不额外拆表。

所有运行、失败、确认、备注和归档操作同步写入现有 `member_crm_audit_log`。

## 后续工作流

### 岗位推荐

1. 使用已确认的候选人画像；
2. 本地岗位有效性和硬条件过滤；
3. 复用现有匹配引擎召回和评分；
4. 只把前 10–20 个岗位交给模型重排；
5. 保存带证据、风险和缺口的内部推荐清单；
6. 顾问确认后再加入会员的指定岗位合集。

### 定制简历

1. 选择已确认画像、来源简历和一个目标岗位；
2. 提取 JD 结构；
3. 生成定制策略和 Resume AST；
4. Claim Verifier 检查每项新增或强化表达；
5. 展示新增、改写、删除、重排和风险差异；
6. 顾问确认后导出为 CRM 内部简历，不同步 C 端。

## 配置

- `ALIBABA_BAILIAN_API_KEY`：推荐使用的服务端密钥；
- `ALIBABA_BAILIAN_CRM_AGENT_MODEL`：可选，默认 `qwen-plus`；
- `ALIBABA_BAILIAN_CN_BASE_URL`：可选，默认内地 DashScope OpenAI 兼容端点；服务端会拒绝非 `dashscope.aliyuncs.com` 域名。

密钥只读取服务端变量，不读取任何 `VITE_` 前缀变量，避免密钥进入前端构建产物。
