# 可信企业岗位采集与 URL 复核运行说明

更新于 2026-09-22，按本轮收紧后的需求执行。本文替代 9 月 20 日方案中的自动发现与每日采集安排。代码完成自检后仍保持默认停用，本轮没有执行生产迁移、部署、岗位发布或企业资料修改。

## 人工采集流程

1. 在“可信企业”的“抓取岗位数据”按钮进入当前企业的同步面板。建立来源并核对已知招聘入口、平台、企业归属和能力；允许人工预检不等于启用自动采集。
2. 点击“预检招聘来源”。预检读取完整列表和正文，核对分页、数量、重复身份、详情覆盖、零结果及异常下降；只保存临时检测记录，不生成候选、不改变正式岗位或企业资料。
3. 在“检测记录”核对报告和原文样本。缺正文、未读完、分页重复、零结果或数量骤降会阻断后续处理，不能靠确认按钮绕过。没有稳定解析器的来源走人工辅助录入。
4. 通过后，管理员确认**本次**预检。确认绑定来源版本、任务、企业和审核人；来源改动或任务超过一小时须重新检测。生成候选直接使用已确认的完整快照，避免确认后第二次请求取得另一份残缺内容。
5. 在“全部待审核”审核候选。现有岗位更新默认不勾选任何字段，必须逐字段确认；新增可编辑后批准，关闭额外展示并确认理由。批量审核也采用实际勾选字段和编辑值。最终发布前再次检查岗位和证据版本。

预检需要读取列表和正文才能验证完整性，但它没有发布权限。人工确认预检也不是确认发布：正式岗位始终保留最后一次批准的内容，直到管理员批准具体变更。

## 数据保护

- 岗位分类、标签、经验等级、推测的地域分类和“中国友好”标记不由采集推断或覆盖；企业分类、联系人、图片、简介、会员/内推配置等不进入采集写入路径。
- 地点、薪资、时区仅保留来源明确提供的值；未知值、空串、空数组和 null 不清空已有字段。源站未提供日期时不伪造源站日期；数据库保留可为空的 `source_published_at`，现有必填 `published_at` 仍承担本站业务发布时间用途。
- 资格识别覆盖明确远程的中国、港澳台、APAC 和全球岗位；语言要求不能代替地域资格，常住地或工作许可限制仍进入人工判断。
- 发布调用 PostgreSQL 原子函数，岗位写入、候选状态、审计、在招统计和发布后任务一起成功或回滚。已有岗位保留原 ID，会员、内推、人工译文等未选字段保持不变。
- 来源迁移、过期租约、并发编辑、重复批准和陈旧证据均有版本检查。旧生产路由、旧后台接口和本地服务器直连的旧爬虫处理器均已封闭；不要通过恢复旧处理器回滚。
- 唯一自动清理是过期的采集暂存和未被审核引用的原始快照。正式岗位、审核依据和审计不因此删除。

## URL 检查与待审核数量

“检查现有岗位申请链接”独立于招聘来源采集，可以检查已有详细岗位和申请 URL，即使企业招聘列表无法完整抓取。人工每次检查 10 条，优先尚未检查或较旧的记录；明确失效生成关闭建议。

404/410 仅在能确定具体岗位身份且未发生跳转时作为证据；403、429、5xx、超时、验证码、首页跳转、通用表单、无法匹配岗位身份以及结构化数据与关闭文案矛盾，均为“无法确定”，不下架。GET 检测记录中保留具体原因。关闭建议批准时再次核对岗位版本、URL 和 24 小时内的有效关闭证据。

**待审核是独立复核状态，不自动撤销 `is_approved`，也不自动把 `status` 改为 inactive。** 新“待审核”列按岗位去重统计来源候选和原有 active 未审核岗位；存量新候选也计入。已暂缓事项仍可见并计入。“全部待审核”查看来源建议，“已录入待审核岗位”进入原有岗位编辑流程。

“在招岗位”统一为 `status='active' AND is_approved IS TRUE`，排序也按实时数量。点击进入的弹窗默认采用完全相同条件；切换“已录入待审核”或“全部岗位”不会覆盖在招数。管理员请求不使用共享缓存；读取失败明确提示过期风险，不把缓存数冒充实时统计。并发编辑后的数量在刷新或关闭管理面板时重新读取。

## 调度与开关

| 项目 | 行为 |
|---|---|
| 企业采集 | 只由人工创建预检任务；绝不按来源到期时间自动创建任务 |
| 持久任务 worker | 手动提交后立即启动；每 10 分钟补处理人工已提交的队列，支持关页面后继续和分页续跑 |
| URL 巡检 | 每 30 分钟领取未检查、岗位已编辑或超过 24 小时的链接；每条正常岗位每天一次，不产生新岗位采集 |
| 候选翻译 | 默认关闭；手动生成或单独开启候选翻译开关；只修改候选 |
| 发布后任务 | 每 5 分钟重试已批准的企业历史与画像刷新，同企业任务合并处理 |
| 全局开关 | `JOB_SYNC_ENABLED=false` 默认停用后台 worker 与定时 URL 巡检；手动 URL 检查和人工审核仍可进行 |
| 翻译开关 | `JOB_SYNC_TRANSLATE_ENABLED=false` |

网络请求校验公开 HTTP/HTTPS、解析地址及每次重定向，同域限速，超时实际取消。任务最多 4 并发、180 秒预算，过期租约不能提交。旧 091 阶段的未完成任务和未审核采集候选在升级时冻结/标为过时，必须走新预检流程。

## 迁移与验收

先在隔离的 Neon 测试分支执行，明确目标连接后再运行实际迁移。091 建立基础表与原子审核，092 增加人工预检门禁及 URL 记录。现有岗位事件继续复用 089 等业务迁移。

```sh
node scripts/run-sql-migration.mjs --dry-run 091_trusted_job_sync.sql
node scripts/run-sql-migration.mjs --dry-run 092_job_sync_manual_gate.sql
# 确认 DATABASE_URL 指向隔离测试库后执行，以下命令会改动该测试库：
node scripts/run-sql-migration.mjs --database-url-env=DATABASE_URL 091_trusted_job_sync.sql
node scripts/run-sql-migration.mjs --database-url-env=DATABASE_URL 092_job_sync_manual_gate.sql
```

保持开关关闭，部署匹配的新 API 与前端，再在测试环境初始化来源、检查配置、开启任务处理，逐个演练预检、取消确认、确认生成、逐字段审核、拒绝和 URL 故障。人工验证通过后再按项目发布流程推广。不得仅部署前端或在缺少 092 的情况下启用任务。

本地不连接生产库的验证：

```sh
npm run test:job-sync
npm run build
node test-cron-policy.js
node test-admin-job-reliability.js
node test-admin-company-job-regressions.js
node test-processed-jobs-write-policy.js
```

专项测试执行实际 PostgreSQL 迁移和函数，验证预检和候选生成前后正式岗位、企业字段、提醒与 outbox 完全不变；覆盖人工字段保护、空值覆盖拦截、失效仅入审核、错误页面、失效证据过期、来源修改、候选去重、关闭后保留原文和旧入口停用。

只读公开接口预检脚本与后台共用完整性判断；它不写数据库，也不能代替后台人工确认：

```sh
npm run job-sync:probe -- Canonical Supabase --output=/tmp/job-sync-preflight.json
```

实际公开来源的既有报告仅覆盖 9 月 20 日新适配器实测的 8 家；本轮重点为隔离测试，没有把其余来源标记成已通过。复杂 ATS/浏览器 worker、生产部署及生产观察尚未完成。

## mini-preview 网站验收

本模块使用独立的 `npm run deploy:job-sync-preview`，不要使用会联动 CloudRun/微信包的旧小程序发布命令。它默认只读，明确 `--apply` 后才执行预发迁移、部署和切换。配置准备、数据保护检查及人工验收步骤见 [预发验收说明](qa/job-sync-preview-acceptance.md)；成功发布后生成 [发布证据](qa/job-sync-preview-release.json)。

预发快照不安装定时任务，仅启用人工提交后的 worker。超过单次执行预算的任务需要管理员再次触发处理，不能把预发环境当作已启用周期调度的生产环境。来源的预检确认与候选审核仍是两次独立的人工决定。
