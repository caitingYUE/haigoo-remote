# Haigoo 小程序设计系统

> 适用范围：Haigoo Remote 微信小程序 1.0 及后续页面。  
> 产品定位：以 Match 为核心的个性化远程职业产品。  
> 设计方向：Personal Match × Modern Clarity × Quiet Energy。  
> 上位文档：`PRODUCT.md`、`docs/haigoo-platform-positioning.md`。

## 1. 产品体验

- 小程序不是官网的移动端复制版。官网负责开放和通用发现，小程序负责个性化 Match。
- Match 是默认目的地、核心功能、最强一级入口和未来功能的组织中心。
- 用户通过职业方向或简历建立偏好，获得少量、可解释、可继续行动的企业和岗位结果。
- 企业页用于主动查找和补充探索；笔记页围绕远程工作、职业方向与长期成长；个人中心负责跨端数据和服务。
- 产品应提供类似“揭晓一张适合自己的卡片”的期待与情绪价值，但不使用赌博、稀缺、倒计时、夸张音效或滑动即决策。
- 匹配结论必须来自真实数据和用户偏好。视觉可以有吸引力，事实不能被包装替代。

## 2. 核心体验原则

### 2.1 一屏一个判断

Match 的前景卡只帮助用户完成一个判断：这家公司是否值得我进一步了解。

单张卡片必须在数秒内回答：

- 这是谁？
- 为什么与我有关？
- 当前有什么代表机会？
- 信息是否新鲜？
- 下一步去哪里看？

### 2.2 情绪价值来自节奏

情绪价值使用：

- 卡片揭晓和层级运动。
- 企业品牌、排版和留白。
- 与用户方向相关的短句。
- 明确但不过度承诺的结果数量和位置反馈。

不使用：

- AI 套话。
- 大段“为什么推荐你”。
- 没有结构化依据、无法解释或数据覆盖不足的伪精确匹配分数。
- 过多彩色标签。
- 强迫关注或连续权限弹窗。

### 2.3 操作必须显式

- 左右滑动只切换企业。
- 点击卡片主体进入企业详情。
- 点击代表岗位进入岗位详情。
- 关注、取关和微信提醒均由明确控件触发。
- 卡片不使用“左滑不喜欢 / 右滑喜欢”的隐藏语义。

## 3. 视觉语言

### 3.1 核心色

```text
页面背景       #F4F6F8
一级内容表面   #FFFFFF
次级内容表面   #F7F8FA
主文字         #141820
次文字         #465264
弱文字         #748094
细边框         #E2E6EB
强边框         #CDD3DC
品牌橙         #E96832
交互橙         #C94F22
浅橙表面       #FFF2EB
成功绿         #356F55
危险红         #9B2C2C
```

使用规则：

- 黑白和冷灰承担 85% 以上的界面。
- 橙色只承担品牌、当前选中、关注状态和少量关键强调。
- Match 主卡的大面积底色仍为白色，不使用整卡橙色、整页深色或渐变。
- 企业 Logo 保留真实品牌色，但周围界面保持中性。
- 会员金只出现在真实会员身份和权益，不进入 Match 普通状态。

### 3.2 圆角

```text
小控件          8px
输入与按钮      10px
普通列表容器    12px
Match 主卡      16px
药丸标签        999px，仅用于短标签和状态
```

- 普通列表禁止 20px 以上大圆角。
- Match 因叠放和手势可使用 16px，但卡内模块不得继续嵌套大圆角卡片。
- Logo 容器使用 10–12px，不使用过度膨胀的软方块。

### 3.3 深度

- 普通页面、企业列表和内容列表依靠背景、边框、分隔线建立层级，默认无阴影。
- Match 前景卡允许一层柔和阴影：有轻微垂直偏移、低不透明度、无彩色光晕。
- 后方卡通过位移、缩放、亮度和轻微旋转表达层级，不叠加多重重阴影。
- 底部 Tab 使用实色表面、顶部细线和安全区填充，不使用悬浮玻璃或半透明渐变。

### 3.4 字体与字号

- 字体：`PingFang SC`、系统中文无衬线；英文使用系统 sans。
- 中文承担全部任务信息，英文只用于 `HaigooRemote`、`Match` 等品牌标识。
- 正文实际显示不小于 15px；辅助信息不小于 12px。
- 企业名 24–28px，Match 页面标题 28–32px，代表岗位 16–18px。
- 避免全大写长英文眉题。`REMOTE MATCH` 只可作为小型气氛眉题，不能承担主要信息。
- 字重以 400、500、600、700 为主，不使用大面积 800/900。

## 4. 全局结构

### 4.1 顶部栏

- 三个一级页面统一使用不透明白色顶部栏。
- 左侧为 `海狗远程 HaigooRemote`，右侧为个人头像。
- 未读状态依附头像，不增加独立通知图标。
- 顶部栏必须根据状态栏和微信胶囊动态计算，滚动时内容不得进入胶囊区域。

### 4.2 底部 Tab

固定为：

1. 企业
2. Match
3. 笔记

规则：

- Tab 表面覆盖完整底部安全区，高度稳定，不允许正文透出或被遮挡。
- 页面底部 padding 必须等于 Tab 可视高度加安全区。
- Match 图标比两侧图标大 35%–40%，不是 2 倍；中心图标可上移 4–6px，但不能突破 Tab 表面形成断裂圆球。
- 三个标签基线一致，Match 标签不得贴近 Home Indicator。
- 激活态使用图标、文字和品牌橙共同表达；非激活态保持清晰，不低于 `#667085`。
- Tab 按压只使用短暂亮度或背景变化，不使用弹跳缩放。

## 5. Match 页面

### 5.1 页面结构

1. 顶部品牌栏。
2. 结果标题 `更懂你的远程企业` 与独立页码；不需要额外英文眉题。
3. 一行可编辑的方向摘要。
4. 三层企业卡组。
5. 页码、轻量滑动提示和必要的恢复状态。
6. 固定底部 Tab。

首屏必须完整露出：页面标题、主卡企业身份、匹配结论和代表岗位。不要让前景卡高到只能看见企业 Logo 和半段正文。

### 5.2 Match 卡片信息架构

从上到下固定为：

1. 企业 Logo、企业名、行业和规模。
2. 右上角可点击的参考匹配度环；数据不足时显示等级而不是数字。
3. 总部地点与有来源的公开评分。
4. 一句来自企业简介的克制概况，最多两行。
5. 两至三个结构化匹配依据，必须来自用户设置、企业资料或公开岗位数据。
6. 一个代表岗位入口；有多个岗位时显示具体岗位方向。
7. 核验时间、轻量关注和 `查看企业`，组成紧凑底栏。

禁止出现：

- 独立的“为什么推荐给你”大标题。
- 三条以上理由。
- 大段推荐语、鸡汤或 AI 总结。
- 一个占满卡片宽度的“关注岗位动态”橙色按钮。
- `关注岗位动态 + 开启微信提醒 + 查看企业详情` 三层底部动作堆叠。
- 黑色“持续核验”胶囊、过多边框和卡内卡。
- 为填满卡片而制造的大面积空白。

### 5.3 参考匹配度

- 默认使用 `一般 / 中等 / 较高 / 高 / 极高` 五档匹配程度，视觉直径 44–48px，避免在小圆环内堆叠数字和长文案。
- 点击后使用底部 Sheet 展示职业方向、企业偏好、机会状态三个维度以及数据覆盖度。
- 推荐权重：职业方向 50%、企业偏好 30%、岗位有效性与新鲜度 20%。最终实现必须以服务端同一公式为准。
- 点击匹配程度后仍可查看方向、偏好与机会信号的计算依据；数据覆盖不足时明确说明，不展示伪精确分数。
- 匹配度只表达“当前设置与现有公开数据的接近程度”，不表达录用概率、职业价值或成功承诺。
- 匹配度环只在前景卡完整显示；后方卡不重复展示动画。

### 5.4 主动作

- 整张卡片主体是 `查看企业` 的大触控区域，但代表岗位有独立点击区域。
- 关注使用紧凑底栏中的图标与状态文本，未关注为描边或中性，已关注为浅橙状态；右上角空间固定留给参考匹配度。
- 用户关注成功后用轻量 Toast 或就地状态确认，不立刻用大弹窗打断下一张卡。
- 微信提醒在关注成功后的后续操作区、个人中心或企业详情中提供，不常驻占据主卡底部。

### 5.5 卡组运动

- 使用微信原生 Swiper，手势距离、速度和方向判定由原生组件负责；不叠加自定义逐帧拖动。
- 两侧透出卡片；保留当前卡片尺寸及 64rpx 的前后边距，不用视觉打磨改变几何参数。
- 左滑查看下一张、右滑返回上一张，首尾循环。
- 过渡为 280ms / easeOutCubic；只有 touch 来源切换更新活动卡，程序切换不重复触发曝光。
- 卡片移动超过 8px 或手势取消后抑制点击，不触发关注、岗位跳转或分数说明。
- 不使用粒子、闪光、彩带、音效或持续脉冲。
- 减弱动态模式关闭附加 CSS 缩放过渡和骨架动画；原生 Swiper 跟随平台行为，不声明已改变原生动画。

## 6. 企业列表

企业页需要比 Match 更高密度，但必须与 Match 共用同一套企业身份、字号、关注状态和颜色规则。

### 6.1 页面工具区

- 标题、总数、搜索和行业筛选构成一个连续工具区。
- 搜索框高度 48px 左右、圆角 10px；不使用粗大 26px 圆角。
- 行业筛选使用紧凑横向 chips，激活态为深墨或浅橙，不能每个都像独立大按钮。
- 工具区滚动时可固定，但必须与顶部栏形成清楚的两层结构。

### 6.2 企业行

推荐采用轻量独立卡片列表。卡片提供必要的聚合和触控边界，但不能恢复厚重粗框大卡：

- 单卡高度约 112–132px，卡间距 10–12px。
- Logo 52–56px，圆角 10–12px。
- 企业名为第一视觉重点；行业和规模为第二层。
- 第三层显示 `总部 · 城市` 与 `★ 4.5`；缺失字段自然收起。
- 岗位摘要使用品牌橙或深墨强调，优先显示 `产品、前端可申请` 等具体方向。
- 右侧关注控件宽度稳定，不挤压企业名。
- 卡片使用 12px 圆角以及“细边框或轻阴影”其中一种，不同时叠加。
- 长英文企业名允许两行或使用合理缩小，不允许与关注按钮碰撞。

### 6.3 一致性

- 企业列表与 Match 必须共用 Logo 回退、关注按钮、企业元信息和岗位摘要组件。
- 同一企业在两个页面的关注状态、名称、行业、规模和开放岗位口径一致。
- Match 可以更具氛围，企业列表必须更高效；两者不能像来自不同产品。

## 7. 笔记与个人中心

- 笔记保留内容优先的连续列表，减少卡片化。
- 推荐内容应能与用户职业方向产生关联，但必须清楚区分“与你方向相关”和“会员内容”。
- 个人中心优先展示 Match 方向、关注企业和岗位更新，再展示会员和服务。
- 会员入口不应成为个人中心第一视觉主角，除非用户正在处理真实会员任务。

## 8. 文案

语气：清楚、平静、轻快、有判断力。

推荐：

- `更懂你的远程企业`
- `93 参考匹配度`
- `查看匹配依据`
- `与你的产品管理方向一致`
- `正在开放 Product Manager 岗位`
- `总部 · 旧金山`
- `★ 4.5 公开评分`
- `产品、前端可申请`
- `查看岗位`
- `查看企业`
- `关注企业`
- `已关注`
- `编辑方向`

避免：

- `为什么推荐给你`
- `产品、项目有相关岗位`
- `基于 AI 多维度分析`
- `精准命中你的职业偏好`
- `录用概率 93%`
- `持续核验`
- `反复比较`
- `开启你的远程职业新篇章`

状态文案必须说明下一步：

- `暂时无法更新，仍在展示有效期内的上次结果。`
- `当前方向暂无合适企业，调整一个方向后再试。`
- `关注已保存。你可以稍后在企业详情中开启微信提醒。`

## 9. 移动交互与无障碍

- 触控目标至少 44px / 88rpx，相邻操作至少 8px / 16rpx。
- 卡片主体、岗位入口、关注、编辑方向、头像和 Tab 均提供明确读屏名称。
- 页码使用 `第 1 家，共 5 家` 的可访问描述。
- 不单靠颜色表达关注、激活或错误。
- 横向卡片手势只有在明确水平移动后接管，避免阻塞纵向滚动和系统返回手势。
- 加载使用卡片形状骨架；错误、空状态和过期状态都有可恢复入口。
- 所有一级页面保留顶部和底部安全区。

## 10. 禁止模式

- 泛 AI SaaS：渐变、霓虹、玻璃、发光描边、脑图式理由。
- 粗糙大卡：大圆角、粗边框、厚阴影、超大空白和多个嵌套面板。
- 游戏化过度：稀有度、多星等级、开箱光效、音效、连击、剩余次数焦虑。这里不包括有明确来源的企业公开评分。
- 营销过度：大橙按钮遍布全站、连续升级 CTA、会员权益抢占核心任务。
- 操作歧义：滑动改变关注、隐藏手势承担关键动作、权限失败回滚关注。
- 跨页面漂移：同一操作出现不同图标、颜色、文案、尺寸和位置。

## 11. 发布前检查

- Match 首屏在 320–430px 宽度设备上完整呈现核心判断信息。
- 前后卡层级清楚，但没有页面横向溢出。
- Tab 背景覆盖安全区，不遮挡卡片、页码或列表末项。
- 企业列表长名称、无 Logo、无岗位、多岗位和已关注状态均不变形。
- 游客、未绑定、免费、有效会员和过期会员的权限与文案真实。
- 加载、缓存、过期、空数据、错误、关注成功和关注失败状态完整。
- 开启减弱动态后 Match 仍可理解和操作。
- TypeScript、设计门禁、运行时检查、真机关键路径与同视口截图对比通过。
