# Haigoo 小程序稳定加载与页面保留体验设计规格

- 日期：2026-09-10
- 状态：已完成对话评审，待书面规格复核
- 设计路径：Architectural
- 目标版本：1.0.30 体验版后续优化
- 覆盖范围：企业列表、企业详情、岗位详情、笔记列表与详情、Match 卡片、会员方案
- 上位约束：`PRODUCT.md`、`docs/haigoo-mini-design-system.md`、现有 Match 与企业目录规格

## 1. 背景与问题

小程序的数据、基本功能和主要链路已经可用，但多个页面仍把后台请求直接映射成整页卸载、空白或全页加载文案：

- 企业列表切换排序时立即清空当前结果，列表被骨架屏替换。
- 企业详情每次 `useDidShow` 都主动清空企业与权限数据，从岗位详情返回也会重新显示“正在加载企业资料”。
- 岗位详情、笔记详情和会员方案依赖页面局部状态，页面重建后无法立即恢复已看内容。
- 笔记列表已有页面级保留逻辑，但缓存不跨页面实例，重新进入仍可能出现明显骨架。
- Match 卡片只为当前 active 卡渲染部分操作组件，滑动过渡中的下一张卡结构不完整，图标会延后出现。

这些表现让正常网络请求看起来像页面异常，也造成用户对导航、排序和返回操作缺少连续感。

## 2. 设计目标

1. 页面结构在排序、筛选、返回和后台刷新期间保持稳定。
2. 已成功打开过的内容再次进入时立即可见，后台更新不阻塞阅读与操作。
3. 只有首次访问且没有任何可用内容时才展示页面级骨架或加载状态。
4. 数据更新完成后原位替换内容，不通过整页卸载表达刷新。
5. 账号、登录态或会员权限变化时，不展示上一身份的受限数据。
6. 不新增全局状态库，不改变现有后端接口和权限规则。

## 3. 方案选择

采用“会话隔离的进程内保留缓存 + stale-while-revalidate 后台刷新”。

现有 `use-retained-resource` 继续作为统一入口，但补足以下能力：

- 缓存从单个 hook 实例提升为模块级内存缓存，页面销毁后同一小程序进程内仍可恢复。
- 缓存键由会话作用域和资源键共同组成。
- 相同作用域内切换查询键时允许保留当前内容，直到新结果返回。
- 已有缓存时先同步恢复内容，再决定是否后台刷新。
- 请求失败且有旧内容时保留旧内容并使用非阻断提示；无旧内容时才显示完整错误态。
- 缓存设数量上限并按最近使用顺序淘汰，避免长时间使用后无界增长。

不采用以下方案：

- 不在每个页面重复实现独立缓存；这会继续造成加载规则分裂。
- 不把企业详情、联系人或会员方案长期写入本地存储；受限数据不应跨进程长期保留。
- 不引入 Redux、Zustand 等新依赖；当前问题只需要小型资源缓存。
- 不把完整详情数据塞进路由参数；体积、权限校验和数据一致性都不合适。

## 4. 共享资源状态模型

每个资源具有四种可见状态：

1. `initial-loading`：无缓存且首次请求中，显示与目标页面结构一致的骨架。
2. `ready`：已有有效内容，正常显示。
3. `refreshing`：已有内容且后台请求中，保留页面，只显示轻量更新状态。
4. `error`：无内容时显示完整错误态；有内容时保留内容并提示更新失败。

通用规则：

- `loading` 只表示“没有可显示数据的首次加载”。
- `refreshing` 表示“当前内容仍可见的后台更新”。
- 同一个资源键的并发请求合并或以最新序列为准，旧响应不得覆盖新结果。
- 切换搜索、行业或排序时，旧列表可暂时保留，但控件立即反映用户刚选择的条件，并显示更新状态。
- 新请求成功后一次性替换列表，避免逐项抖动。
- 下拉刷新、支付完成等用户明确要求最新结果的动作可以强制请求，但仍不清空已有内容。

## 5. 会话与权限隔离

缓存作用域继续基于 `miniContentScope()`，至少包含：

- 当前环境与会话身份。
- 用户 ID 或匿名状态。
- 会员状态、会员类型、到期时间和是否已过期。

安全规则：

- 作用域变化时不得沿用上一作用域缓存，也不得保留屏幕上的旧数据等待新请求。
- 企业详情中的联系人访问权限必须在每次页面重新显示时后台复核。
- 权限复核期间可保留同一作用域内已显示的详情；收到 `401`、`403`、会话变化或权限降级后立即移除受限内容。
- 会员方案页先刷新微信会话，再按刷新后的作用域读取或请求方案，避免把旧会员状态写进新作用域。
- 模块缓存只存在于当前小程序进程，不持久化到 Storage。

## 6. 企业列表交互

### 6.1 排序菜单

- 当前排序按钮显示 `按最新` 或 `按相关度`，并使用向下箭头表达可展开。
- 点击按钮只打开锚定在按钮下方的下拉菜单，不立即切换排序。
- 菜单包含 `按最新` 和 `按相关度` 两项；当前项同时使用勾选图标与选中样式，不只依赖颜色。
- 选择当前项只关闭菜单，不发起重复请求。
- 选择另一项后立即更新按钮标签、关闭菜单并从第一页请求新排序。
- 点击菜单外区域关闭菜单，不修改排序。
- 菜单打开时提供 `aria-expanded`，选项提供 `aria-selected`。

### 6.2 列表刷新

- 排序、搜索、行业筛选、下拉刷新期间保留现有列表和滚动结构。
- 列表顶部出现固定高度的紧凑加载状态，文案按场景使用 `正在更新企业`。
- 加载状态不覆盖搜索框、筛选项或企业卡片，不导致列表整体高度跳变。
- 更新成功后原位替换列表；更新失败时保留原列表并提示“暂时无法更新，已保留上次内容”。
- 首次进入且无缓存时仍可显示企业卡片骨架。
- 加载更多只更新列表底部按钮，不触发顶部刷新状态。

### 6.3 卡片视觉与文案

- `NEW` 使用清晰的成功绿色文字，保留文字信号，不改为纯色圆点。
- 信息顺序固定为：企业名、评分标签、`NEW`。
- `NEW` 仅在现有三天更新规则满足时显示，不修改数据判断。
- 岗位方向摘要后缀从 `岗位可关注` / `等岗位可关注` 调整为 `方向可关注` / `等方向可关注`。
- 无岗位方向数据时继续显示现有缺失文案，不制造方向。

## 7. 详情页连续性

### 7.1 企业详情

- 资源键包含企业 ID 与精确搜索授权参数。
- 首次无缓存时显示结构骨架，不使用孤立的整页“正在加载企业资料”文本。
- 从岗位详情返回时立即保留企业详情、当前 Tab、滚动位置和底部操作区。
- `useDidShow` 触发后台复核，但不得先执行 `setCompany(null)` 或 `setAccess(null)`。
- 后台复核失败时保留同一权限作用域内的公开内容；受限联系人按第 5 节规则处理。

### 7.2 岗位详情

- 资源键包含企业 ID、岗位 ID 与精确搜索授权参数。
- 再次打开已看岗位时先恢复岗位与企业标识，再后台刷新岗位和收藏状态。
- 收藏状态单独更新，不阻塞岗位正文；收藏状态失败只影响收藏控件。
- 首次无缓存时使用稳定骨架，不显示导致整页空白的加载文本。

### 7.3 笔记列表与详情

- 笔记列表保留搜索词、主题和已加载内容，后台刷新时列表继续可读。
- 笔记详情按笔记 ID 缓存公开或当前作用域可见的结果。
- 相关文章请求失败不影响正文展示。
- 首次无缓存时使用文章结构骨架；再次进入不重复显示“正在打开笔记”。

## 8. Match 卡片稳定性

- 保持所有 Swiper 卡片的 Logo 容器、操作区和必要图标结构常驻。
- 非当前卡片保持不可点击、不可聚焦和正确的 `aria-hidden`，但不通过条件卸载破坏几何结构。
- 卡片切换只改变 active 状态和交互权限，不重建企业 Logo 或底部操作区。
- 公司 Logo 继续使用已解析 URL 和首字回退；滑动卡片时不重复发起相同云文件解析。
- Match 已有本地有效快照时首帧直接使用快照，后台请求不得把结果页退回全屏加载页。
- 用户主动生成新匹配结果时可以显示明确进度，但旧结果存在时仍优先保持稳定结构。

## 9. 会员方案页

- 将方案、会员摘要和支付可用状态作为一个保留资源管理。
- 重新进入页面时先显示同一作用域内上次成功方案，再刷新会话和服务端方案。
- 后台更新只在方案区顶部显示轻量状态，不把方案卡、权益和购买区替换成骨架。
- 支付完成后强制刷新并保持原页面结构；确认新权益后原位更新会员摘要和按钮文案。
- 首次无缓存或权限作用域变化时才使用现有方案骨架。

## 10. 视觉与动效约束

- 加载反馈使用品牌现有橙色与中性色，不新增页面级主色。
- 顶部加载状态高度固定，出现和消失不推动列表产生明显跳动。
- 排序菜单使用白色实面、细边框、轻阴影和不超过现有控件体系的圆角。
- 不使用全屏遮罩、全屏 spinner 或持续闪烁动画表达普通刷新。
- 遵循系统减弱动画设置；加载旋转可以停止但必须保留文字状态。
- 所有新增触控区域至少 `88rpx`，文本在小屏和大字号下不得截断关键选项。

## 11. 错误与竞态

- 搜索、筛选和排序连续变化时只接受最新请求结果。
- 用户离开页面后完成的请求不得更新已销毁实例。
- 同一资源刷新失败不覆盖上次成功数据。
- 页面首次请求失败且无缓存时提供重试；重试使用当前已提交的搜索、筛选和排序条件。
- 账号切换时立即清除页面上旧作用域数据，即使旧请求稍后成功也不得恢复。
- 后台刷新期间禁用会产生重复请求的同一排序项；其他导航保持可用。

## 13. 测试与验收

### 13.1 自动化

- 保留资源在页面实例重建后可同步恢复。
- 相同作用域切换 key 时旧内容保留，新结果成功后替换。
- 账号或会员作用域变化立即清除旧缓存和页面数据。
- `401`、`403` 和会话变化不会保留受限内容。
- 企业排序按钮先打开菜单，选择后才请求对应 `sortBy`。
- 排序请求期间旧企业列表仍存在，最新响应覆盖旧结果，过期响应被忽略。
- 企业详情返回时不主动清空企业与权限数据。
- 岗位、笔记和会员已有缓存时不回退到全屏加载文案。
- Match 非 active 卡片保留稳定 Logo 与操作区结构，但不可交互。
- `NEW` 位于评分之后且使用绿色；方向摘要文案符合新要求。

### 13.2 构建检查

- 运行相关小程序回归测试。
- 运行 `npm --prefix miniprogram run type-check`。
- 运行 `git diff --check`。
- 构建 1.0.30 experience 包并运行现有体验版检查，但不上传、不部署。

### 13.3 人工链路

1. 企业列表切换两种排序，确认菜单预期明确且列表不消失。
2. 企业列表进入企业详情，再进入岗位详情并返回两次，确认详情和列表都不空屏。
3. 打开笔记列表与笔记详情后返回并再次进入，确认内容立即恢复。
4. 连续滑动 Match 卡片，确认 Logo、操作图标和卡片高度稳定。
5. 打开会员页、返回再进入，确认方案结构立即出现并后台刷新。
6. 切换账号、退出登录和模拟会员过期，确认旧联系人与会员内容不会短暂泄露。

## 14. 完成标准

- 普通返回、重复进入、排序和刷新不再出现可感知的整页空白。
- 有旧内容时，加载状态不改变页面主结构。
- 无旧内容时，首次骨架与目标页面几何结构一致。
- 权限隔离和竞态测试通过。
- 现有企业、岗位、笔记、Match、收藏、关注和支付功能不回归。
- 体验版构建与检查通过后，形成可供重新上传体验版的源代码状态。
