# Haigoo 小程序企业目录搜索、排序与内容同步设计规格

- 日期：2026-09-09
- 状态：对话设计已确认，待书面规格复核
- 设计路径：Architectural
- 适用环境：Vercel Preview、CloudBase 开发环境、小程序体验版
- 明确不包含：Vercel Production、CloudBase 生产环境、生产账号/支付数据写入

## 1. 背景与已确认根因

企业目录当前同时依赖 Vercel Preview 的账号权限数据、`trusted_companies` 与 `company_job_history`，并由 CloudBase 开发容器代理给小程序。只读对账确认：

- Preview 有 261 家 `active` 企业，但仅 17 家具有目录查询认可的开放岗位历史。
- Preview `jobs` 表有 1080 条表面满足 `active + is_approved + non-member-only` 的岗位，但没有一条对应的开放 `company_job_history`。
- Preview 的 58 条可见岗位历史又都没有对应的本地 `jobs` 记录，来自过去的正式内容快照。
- 最近 72 小时 Preview 没有企业、岗位历史的有效新增或更新。
- 企业页缓存约 60 秒、Gateway 快照 45 秒、免费名称索引 5 分钟；缓存无法解释超过 12 小时不展示。

问题根因不是“刷新慢”，而是以下契约和同步链路缺口：

1. 免费搜索的 30% 容错候选只包含企业名称，完整岗位名称会在进入岗位查询前被判空。
2. 会员搜索只是数据库子串查询，没有编辑距离容错、文本相关度排序或通配符转义。
3. 小程序、CloudRun、Gateway 均没有 `latest/relevance` 排序参数；数据库固定按岗位历史时间排序。
4. 普通后台岗位保存和部分手动抓取路径只写 `jobs`，不写目录依赖的 `company_job_history`。
5. 体验版目录读取 Preview 企业数据；正式岗位源仅为 Preview 已返回的企业补充岗位元数据，不能带入正式后台新增企业。
6. 岗位历史首次写入时把来源发布日期写进 `first_seen_at`，使“系统新收录”和“来源原始发布日期”混为一谈。
7. NEW 前端组件已经存在，但没有近三天的合格岗位历史可驱动，因此长期不显示。

## 2. 目标与产品边界

### 2.1 目标

- 免费用户可以按完整企业名或完整岗位名搜索，并允许约 30% 的输入错误。
- 会员可以按企业名或岗位名进行中英文模糊搜索，结果按清晰的相关度规则排序。
- 企业目录提供“最新 / 相关度”排序，并保证分页前完成全量排序。
- 正式后台审核通过的新企业与新岗位在开发体验版中最迟一小时内可见。
- 最近 72 小时首次进入公开目录的岗位使所属企业显示 NEW。
- 搜索、列表、企业详情和岗位详情只暴露符合人工审核与公开访问条件的数据。

### 2.2 企业展示边界

企业只有在自身 `trusted_companies.status = 'active'`，且至少存在一个符合全部条件的岗位时进入目录：

1. 岗位属于该可信企业，具有稳定的 `company_id`。
2. `jobs.status = 'active'`。
3. 当前岗位记录的 `jobs.is_approved IS TRUE`，即后台“已审核通过”；没有当前岗位记录的历史快照不能替代审核证明。
4. `COALESCE(jobs.member_only, false) = false`。
5. 岗位具有合法 HTTP/HTTPS 投递链接，或合法的公开招聘邮箱。
6. 岗位没有被正式内容源判定为关闭、过期或不可公开。

只有企业资料、没有上述有效岗位的企业不展示。

`is_approved` 是当前后台 UI “通过审核”的实际数据库字段，没有第二个岗位审核状态字段。Preview 的旧迁移曾为历史数据默认设置 `is_approved = true`，因此 Preview 本地 1080 条记录不能等价为人工审核通过，也不得作为本次回填来源。开发目录只接受正式内容源经签名接口筛选后返回的审核结果，并严格关联同步后的当前岗位投影。

现有代码中 `company_job_history` 在找不到对应 `jobs` 记录时仍可进入目录，这条兼容分支必须删除。搜索、计数、行业聚合、排序和 NEW 共用同一资格集合，核心关系为：

```sql
FROM trusted_companies tc
JOIN company_job_history h
  ON h.company_id = tc.company_id
 AND h.closed_at IS NULL
 AND h.is_public_opportunity IS TRUE
JOIN jobs j
  ON j.job_id = h.source_job_id
 AND j.company_id = tc.company_id
 AND j.status = 'active'
 AND j.is_approved IS TRUE
 AND COALESCE(j.member_only, FALSE) IS FALSE
WHERE tc.status = 'active'
```

## 3. 选定方案

采用“正式公开内容快照安全投影到 Preview + 现有目录契约扩展”的方案。

- 保留现有 Vercel Gateway、CloudBase 开发容器、Taro 企业页和现有数据库表。
- 不引入 Elasticsearch、Algolia、额外搜索服务或新的评分平台。
- 正式内容源负责判断企业与岗位是否可公开；Preview 只保存允许小程序体验版使用的内容投影。
- Preview 继续负责测试账号、会员权限和求职方向。正式内容同步只写企业公开字段、审核通过的公开岗位投影及其历史，不得读写账号、会员、订单、支付、联系人或通知表。
- 企业搜索、分页、排序仍由 Gateway 在数据库查询阶段完成，客户端不对单页结果做伪全局排序。

未选择的方案：

- 只回填 Preview 当前岗位：不能解决正式后台以后新增企业再次缺失的问题。
- 小程序直接使用正式环境全部接口：会破坏 Preview 账号与会员权限隔离，并扩大生产数据访问面。

## 4. 正式内容到 Preview 的安全同步

### 4.1 正式内容快照

扩展现有带 HMAC 签名的只读 Gateway 能力，提供分页公开目录快照。正式端在查询时执行第 2.2 节的全部资格过滤，只返回：

- 企业 ID、名称及翻译、简介、行业、公开标签、地址、规模、成立年份、评分与评分来源、公开 Logo/官网/招聘页。
- 合格岗位的公开展示投影，包括 ID、企业 ID、原文与翻译标题、分类、角色家族、地点、公开描述、来源、首次正式入库时间、来源发布日期和公开投递方式。
- 快照版本、服务端时间、总数、分页信息。

快照不得包含会员联系人、内推联系人、非公开邮箱、用户数据、订单数据或未审核岗位。

### 4.2 Preview 导入

CloudBase 开发容器使用已有网关签名机制拉取完整快照，再调用只允许 Preview 接收的签名导入操作：

1. 先完整读取并校验所有分页，总数、企业引用和快照版本必须一致。
2. 任何分页失败或记录不合格时整次放弃，不修改当前可用快照。
3. 在 Preview 中幂等更新允许公开的 `trusted_companies` 基础字段。
4. 将正式源返回的合格岗位幂等写入 Preview `jobs` 公开投影，并明确写入 `is_approved = true`；不读取或沿用 Preview 本地旧岗位的审核标记。
5. 以同一批合格岗位重建开放 `company_job_history` 投影，保证历史与当前岗位可严格关联。
6. 只有完整快照成功后，才关闭快照中已不存在的旧开放历史，并把本次正式投影中已消失的岗位退出公开资格，防止半次同步把目录清空。
7. 导入不删除企业，以保留 Preview 测试账号的关注和 Match 外键；没有合格岗位的企业自然退出目录。

导入操作必须同时满足：

- 当前部署是 Vercel Preview。
- 显式启用开发内容导入环境变量。
- 请求通过现有 HMAC 时间戳和签名校验。
- 单次记录数、分页数和关闭比例不超过安全上限；异常比例进入失败状态并保留旧快照。

### 4.3 调度与可观测性

- CloudBase 开发容器启动后执行一次非阻塞同步，此后每小时检查一次。
- 同一时刻只允许一个同步任务；使用现有 lease/共享 promise 模式防止并发覆盖。
- 提供仅开发环境可用的手动强制同步入口，供本次部署后对账和故障恢复。
- 保存最近成功版本、成功时间、企业数、岗位数、失败原因和连续失败次数。
- 企业目录请求继续服务最近一次完整成功快照；同步失败不返回空目录。
- 验收目标为正式后台审核通过后 60 分钟内进入体验版，手动强制同步后 5 分钟内可见。

## 5. 岗位历史与时间语义

### 5.1 单一写入边界

所有可能使岗位首次成为“可信企业 + active + 审核通过 + 免费公开”的共享写入路径，在岗位保存成功后调用同一个幂等历史同步函数。资格判断必须使用 `isApproved === true`，不得把缺失审核字段默认成通过。包括：

- 普通后台新增/编辑岗位。
- 企业后台手动抓取。
- 定时企业岗位抓取。
- 链接验证后的关闭与重新开放。
- Preview 正式内容快照导入。

该函数负责创建/更新岗位历史、关闭不再合格的记录，并按需重建企业招聘画像。调用方不各自复制判断条件。

同时硬化审核默认值：

- 企业岗位弹窗新增岗位的前端默认值改为 `isApproved: false`。
- 新的幂等迁移把 `jobs.is_approved` 的数据库默认值设为 `FALSE`。
- 不批量改写已有正式数据的审核值；Preview 旧真值也不参与本次目录回填。
- 生成企业更新事件时同样要求 `isApproved === true`、非会员专属且具有公开投递方式；缺失字段不得默认公开。

### 5.2 时间字段

- `first_seen_at`：岗位第一次成为合格公开岗位并被当前内容环境收录的时间；仅 INSERT 时写 `NOW()`，冲突更新不得修改。
- `source_published_at`：来源网站声明的发布日期，仅作为信息字段，不决定 NEW。
- `last_seen_at`：最近一次同步仍确认岗位有效的时间，不决定 NEW 或最新排序。
- 未来时间不得参与排序或 NEW。

Preview 快照导入时，使用正式内容源的权威首次入库时间作为 `first_seen_at`。这样同一岗位不会因为每小时同步反复变成 NEW。

企业统一派生字段：

```text
latestPublicJobAt = MAX(first_seen_at of eligible open jobs, excluding future values)
newJobsUntil      = latestPublicJobAt + 72 hours
```

“最新”排序和 NEW 共用 `latestPublicJobAt`，不再采用两套时间口径。

## 6. 搜索契约

### 6.1 通用标准化

企业名和岗位名统一执行：

- Unicode NFKC 标准化。
- 转为小写。
- 去除空白、标点和全半角差异。
- 原文、企业翻译名、岗位翻译标题分别作为候选，不把企业简介、岗位描述或行业加入免费精确候选。

用户输入中的 `%`、`_` 和转义字符必须按普通文本处理，不得成为 SQL 通配符。

### 6.2 免费搜索

免费搜索是“完整名称的容错匹配”，不是任意关键词浏览：

- 对完整企业名和完整岗位名使用现有 Damerau-Levenshtein 距离。
- 允许编辑次数 `floor(candidateLength * 0.3)`，等价于约 70% 以上字符相似度。
- 短于 4 个标准化字符的候选只允许完全一致，避免短词枚举全库。
- 企业完全一致优先，其次岗位完全一致，再按归一化编辑距离和最近岗位时间排序。
- 岗位命中时返回所属企业，并在企业级去重。
- 合格候选超过 5 家时返回 `too_broad`，不泄露完整企业目录。
- 搜索结果仍只包含至少一个合格公开岗位的企业。

前端提示改为“输入完整企业或岗位名称”，空态明确区分“名称过于宽泛”和“未找到已审核公开岗位”。

### 6.3 会员搜索

会员搜索支持：

- 企业原文/翻译名的完全一致、前缀、子串和 30% 编辑距离容错。
- 岗位原文/翻译标题的完全一致、前缀、子串和 30% 编辑距离容错。
- 企业级去重；同一企业多个已审核公开岗位命中时取最高文本分。

文本相关度优先级：

1. 企业名完全一致。
2. 岗位名完全一致。
3. 企业名前缀或低编辑距离。
4. 岗位名前缀或低编辑距离。
5. 企业名子串。
6. 岗位名子串。
7. 最近公开岗位时间作为并列项。

实现优先复用现有 `natural` Damerau-Levenshtein 依赖和已有名称标准化函数。首版不新增全文检索服务；上线前测量真实查询 P95，只有超过验收阈值时才评估 PostgreSQL trigram 索引。

## 7. 排序契约

企业接口增加 `sortBy=latest|relevance`，默认 `latest`。该参数从小程序服务层、CloudBase 路由一直透传到 Gateway，并进入缓存键。

### 7.1 最新

```text
latestPublicJobAt DESC, companyName ASC, companyId ASC
```

稳定并列项用于避免翻页重复或漏项。

### 7.2 相关度

有搜索词时：

```text
textRelevance DESC,
careerDirectionMatch DESC,
latestPublicJobAt DESC,
companyName ASC,
companyId ASC
```

无搜索词时：

```text
careerDirectionMatch DESC,
latestPublicJobAt DESC,
companyName ASC,
companyId ASC
```

`careerDirectionMatch` 复用现有 `career_watch_profiles.role_families` 与合格开放岗位 `role_families` 的交集。首版只做“命中优先”的布尔分层，不创建新的黑盒分数系统。没有有效求职方向时，相关度稳定退化为最新排序。

个性化缓存键必须包含用户 ID 和职业方向版本，避免一个会员看到另一个会员的排序。免费用户可以看到排序控件，但其默认 12 家目录和精确搜索权限边界不变。

## 8. 小程序交互

- 搜索框统一提示“搜索企业或岗位名称”；免费态在辅助文案中说明需输入完整名称，可容许少量错字。
- 企业工具区增加紧凑的“最新 / 相关度”双选控件，使用现有品牌橙表示选中态，不增加新的视觉系统。
- 切换排序后回到第一页，清空已加载的分页结果，保留搜索词和行业筛选。
- 搜索、筛选、排序和下拉刷新都纳入已有请求序号防竞态机制。
- 相关度缺少职业方向时仍返回最新顺序，不阻断列表；可显示一次轻量提示，引导到 Match 设置。
- NEW 沿用现有紧凑标签，读屏名称为“近三天有新岗位”。
- 客户端继续防御性过滤不合格企业，但服务端必须保证每页记录都满足契约，避免前端过滤后产生短页。

## 9. 错误处理与数据安全

- 正式快照读取失败：保留最近成功快照，记录失败，不关闭任何现有岗位历史。
- Preview 导入失败：事务回滚；企业目录继续服务旧版本。
- 搜索输入为空、过长或仅包含标点：不执行昂贵模糊计算，按当前排序返回目录或明确提示。
- 相关度所需职业档案读取失败：降级为最新排序，不影响目录可用性。
- 单个岗位标题或企业翻译异常：丢弃该候选字段，不丢弃其他合法候选。
- 所有公开资格判断在服务端完成；客户端参数不能绕过审核、会员专属或关闭状态。
- 正式环境不开放 Preview 导入操作，本次也不部署或写入生产环境。

## 10. 验收与测试

### 10.1 搜索矩阵

覆盖免费/会员与以下候选组合：

- 企业原名、企业中文翻译、岗位原名、岗位中文翻译。
- 完全一致、一处增删、一处换位、约 30% 编辑、超过 30% 编辑。
- 2–3 字符短词、中文、英文大小写、全半角、标点、空格、`%`、`_`、反斜杠。
- 同名岗位跨多个企业、同一企业多个岗位命中、超过 5 家的宽泛候选。

### 10.2 资格矩阵

分别验证：

- active + 正式审核通过 + 免费公开 + 合法投递方式：展示。
- 待审核、撤销审核、inactive、member-only、无公开投递方式、企业 inactive：不展示。
- Preview 本地遗留 `is_approved = true`、但正式内容源未返回：不展示。
- 只有历史记录、没有可严格关联的当前审核通过岗位：不展示。
- 仅公开招聘邮箱的审核通过岗位：展示且可进入公开申请链路。

### 10.3 排序与 NEW

- 至少 30 家、跨 2 页验证最新和相关度均无重复、无漏项、顺序稳定。
- 求职方向命中企业优先；无档案时相关度与最新一致。
- 首次发现 0 小时、71:59:59、72:00:00 边界。
- 来源发布日期很旧但今天首次收录：今天排序靠前并显示 NEW。
- 老岗位今天只更新描述：不重新显示 NEW。
- 未来错误时间不置顶、不显示 NEW。

### 10.4 同步与故障恢复

- 正式快照新增已审核企业和岗位后，强制同步 5 分钟内可见，定时同步 60 分钟内可见。
- 半页失败、总数变化、签名失败和异常关闭比例均保留旧快照。
- 完整快照移除/关闭岗位后，企业无其他合格岗位时退出目录。
- 同步不得修改 Preview 用户、会员、订单、退款、关注、联系人和通知记录。
- 部署后对账正式内容源的合格企业数、合格岗位数、Preview 投影数和小程序目录数，并解释所有差异。

## 11. 发布顺序

1. 先提交纯函数、严格审核 SQL 契约、审核默认值迁移和回归测试。
2. 部署 Vercel Preview 的正式只读快照与 Preview 导入能力。
3. 部署 CloudBase 开发容器的安全同步、排序透传和观测状态。
4. 执行一次手动完整同步并完成数量对账；不得使用 Preview 1080 条旧岗位盲目回填。
5. 发布小程序体验构建，验证免费/会员搜索、两个排序、NEW 和企业详情。
6. 本次不部署生产；生产发布需另行确认。

## 12. 成功标准

- 后台“已审核通过”且存在当前岗位记录的合格公开岗位是企业目录唯一岗位来源；孤立历史不得绕过审核。
- 免费完整企业名和岗位名均具备约 30% 容错，且不开放宽泛目录枚举。
- 会员模糊搜索结果可解释、无 SQL 通配符误命中。
- “最新”和 NEW 使用同一个首次公开收录时间。
- 体验版新增内容不再依赖人工脚本，60 分钟内自动同步。
- Preview 旧审核标记不会导致 1000+ 未人工审核岗位被公开。
