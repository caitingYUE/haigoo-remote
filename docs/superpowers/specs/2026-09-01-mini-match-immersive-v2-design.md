# Haigoo 小程序沉浸式 Match V2.1 设计规格

- 日期：2026-09-01
- 状态：已批准，供 AI Coding 执行
- 设计路径：Architectural
- 覆盖范围：产品定位、Match 页面、企业卡片、企业列表、底部 Tab、跨页视觉一致性
- 上位文档：`PRODUCT.md`、`docs/haigoo-platform-positioning.md`
- 替代关系：本规格覆盖旧规格中的“温暖档案卡”视觉、卡片底部动作层级和相关文案；真实数据、循环卡组、关注与微信提醒解耦等行为继续有效。2026-09-02 起手势改为 14% 位移或合格快速轻扫触发。
- V2.1 修订：强化中心 Match Tab、增加可解释参考匹配度、公开评分、总部地点和具体开放岗位方向，并将企业列表调整为信息重点更明确的轻量卡片。

## 1. 目标

把小程序从“有 Match 功能的企业与内容集合”升级为“以 Match 为产品身份的个性化远程职业产品”。

V2 必须做到：

1. 用户进入结果页后立刻感到这是为自己生成的一组企业，而不是普通企业目录。
2. 卡片具有揭晓感、吸引力和继续滑动的欲望，但不产生赌场、盲盒或幼稚游戏感。
3. 用户能快速判断企业、理解匹配依据并进入企业或岗位详情。
4. 企业列表、Match、顶部栏、Tab 和个人中心来自同一设计系统。
5. 删除当前企业卡片底部的重复动作、AI 套话和大面积无意义留白。

## 2. 体验定位

关键词：Personal、Revealing、Light、Precise、Modern、Calm。

体验类比是“收到一组为你整理好的专业企业卡”，不是招聘网站岗位列表、AI 生成报告、Tinder 左右喜欢/拒绝、抽取稀有卡牌的游戏或会员销售漏斗。

视觉表达采用黑、白、冷灰和品牌橙。科技感来自精确排版、流畅运动、数据新鲜度和组件一致性，不来自霓虹、渐变、玻璃和发光。

## 3. 产品架构

### 3.1 一级导航

- `企业`：主动查找和补充探索。
- `Match`：默认入口、核心结果和最强视觉锚点。
- `笔记`：职业方向相关的成长内容。

Match 居中并明确放大。中心图标应比两侧大 35%–40%，上移 4–6px，标签仍与两侧保持同一基线。禁止继续使用接近两倍尺寸、突破 Tab 表面的巨大圆形图标。

### 3.2 主路径

```text
设置方向 / 导入简历
        ↓
生成一组匹配企业
        ↓
滑动查看企业卡
        ↓
打开企业或代表岗位
        ↓
关注企业
        ↓
按需开启提醒并持续回访
```

关注不是查看卡片的唯一成功标准。打开企业、打开岗位、完成关注和后续回访都属于有效结果。

## 4. Match 页面结构

### 4.1 结果页首屏

从上到下：

1. 共用品牌顶部栏。
2. 结果标题 `更懂你的远程企业`，右侧独立显示 `1 / 5`。
3. 方向摘要 `当前方向 · 产品经理 / 项目管理`，右侧为 `调整`。
4. 三层企业卡组。
5. 页码点；读屏描述使用 `第 1 家，共 5 家`。
6. 固定底部 Tab。

取消：

- `为你匹配` 这种缺少结果感的孤立标题。
- 日期放在标题右上角造成的行政报表感。
- `左右滑动，反复比较` 等说明性废话。首次进入可短暂显示 `左右滑动查看更多`，用户完成一次滑动后消失。

页面不再依赖英文眉题制造层级，由中文标题、方向摘要和卡组本身建立身份。

### 4.2 页面密度

- 375px 宽设备上，前景卡宽度约 327–339px。
- 卡片可见高度约 470–520px，按真实内容自适应，不设置 520px 以上强制空白。
- 主卡顶部与方向摘要间距 20–24px。
- 主卡底部与页码间距 14–18px。
- 后方两张卡各露出 10–18px，不能形成大面积倾斜白边。

## 5. Match 企业卡

### 5.1 内容模型

```text
┌─────────────────────────────┐
│ [Logo]  GitLab       [93 匹配度] │
│         科技 / DevOps · 全远程   │
│  总部 · 旧金山      ★ 4.5       │
│                             │
│ 与你的前端方向和远程偏好高度重合 │
│                             │
│ [方向匹配] [全远程]             │
│                             │
│ 后端工程师（Go）             › │
│ 另有前端、产品岗位可申请        │
│                             │
│ 最近核验 08.31   + 关注  查看 › │
└─────────────────────────────┘
```

### 5.2 企业身份区

- Logo：52–56px，真实 Logo 优先；缺失时使用黑底白字首字回退。
- 企业名：24–28px，最多两行，长英文名不得被关注按钮挤成不可读省略号。
- 元信息：行业和规模放在同一行或自然换行。
- 关注：进入紧凑底栏，使用 44px 触控区域和 `关注 / 已关注`；右上角空间留给参考匹配度。
- 不显示黑色 `持续核验` 胶囊。新鲜度进入底栏。

### 5.3 参考匹配度

- 参考匹配度是卡片最主要的视觉数据点，使用 52–60px 橙色环形组件，数字使用 tabular figures。
- 数字来自服务端结构化计算，不允许客户端用标签数量或文案临时计算。
- 默认权重：职业方向 50%、用户企业偏好 30%、岗位有效性与新鲜度 20%。
- 点击匹配度打开底部 Sheet，显示各维度得分、数据覆盖度和说明。
- `scoreConfidence >= 0.75` 才显示 0–100 数字；低于阈值显示 `值得了解`、`方向相关` 等定性等级。
- 文案固定说明：`基于你当前设置与已核验公开信息，仅用于推荐排序。`
- 禁止将匹配度解释为录用概率、成功率、企业质量总分或职业价值判断。

### 5.4 个人匹配判断

标题使用 `适合你继续了解` 或根据状态使用同等级短标题。

正文最多 36 个中文字符、两行，例如：

- `产品与项目方向吻合，当前有相关远程岗位开放。`
- `团队规模符合你的偏好，并有远程产品岗位。`

正文必须由结构化匹配依据生成或由服务端提供，经文案模板压缩。不得把多个理由直接拼成逗号列表。

### 5.5 匹配依据

- 最多两个。
- 标签文字优先使用事实短语：`产品方向`、`远程岗位`、`中小团队`、`SaaS 行业`。
- 标签为浅橙或中性浅灰小胶囊，高 28–32px。
- 不能出现三到五个粉橙色气泡占据半张卡。

### 5.6 企业事实与代表岗位

- 总部地点来自 `trusted_companies.address` 或明确的翻译字段；只显示城市/国家级摘要。
- 公开评分必须同时具备合法数值和支持的 `ratingSource`；列表可简写为 `★ 4.5`，读屏与详情保留 `公开评分` 和来源。
- 评分和总部缺失时直接收起，不显示占位符。

- 代表岗位是卡片内最明确的内容入口。
- 使用一条扁平行，不做嵌套大卡片。
- 显示岗位名和最多一行关键元信息。
- 右侧明确箭头。
- 有多个相关岗位时显示具体方向，例如 `另有前端、产品岗位可申请`，不使用笼统的 `多个岗位开放申请中`。
- 无可验证岗位时该企业不应进入主要 Match 卡组；降级场景必须明确为企业观察而非在招推荐。

### 5.7 卡片底栏

同一行显示：

- 左：`最近核验 08.31`
- 中：`关注 / 已关注`
- 右：`查看 ›`

禁止在底栏继续放置全宽橙色关注按钮、第二行微信提醒、第三行查看企业详情、独立推荐语或操作教程。

### 5.8 卡片视觉

- 背景：白色。
- 圆角：16px。
- 边框：可选 1px 极浅冷灰；与阴影二选一，避免 ghost card。
- 前景阴影：`0 18px 48px rgba(20, 24, 32, 0.12)` 附近，可根据真机调整。
- 内容 padding：24px。
- 卡内模块用间距和细线组织，不嵌套第二张大卡。
- 卡片上半区允许轻微非对称布局：Logo 与身份靠左、匹配度环靠右；下半区用一块浅暖色岗位面形成视觉落点。
- 后方两张卡使用轻微相反旋转和错位，让轮廓在静止状态下也有层叠生命力。
- 可使用一条 2px 以下的短橙色品牌标记，但不能使用粗侧边框。

## 6. 卡组与手势

### 6.1 层级

- 前景卡：`scale(1)`，旋转由拖动决定。
- 第二张：向上 8–12px，水平偏移 8–12px，`scale(.975)`，亮度略降。
- 第三张：向上 16–22px，水平反向偏移，`scale(.95)`，不透明度 0.7–0.85。
- 后方卡只显示外轮廓和少量企业身份，不要完整暴露文字造成视觉重影。

### 6.2 手势

- 水平位移达到卡宽 14% 切换；快速轻扫在位移达到 24px 后可按速度触发，未达阈值回弹。
- 左右均可循环，保留上次卡片位置。
- 滑动不产生喜欢、拒绝、删除或关注语义。
- 卡片内部按钮必须停止手势传播。
- 页面仍允许正常纵向滚动；只有水平意图明确后才锁定卡片。

### 6.3 动效

- 松手完成切换：220–280ms。
- 回弹：180–240ms。
- 最大旋转：3 度。
- 前景卡离开时，下一张同时向前补位，保持空间连续性。
- 可在第一次卡片出现时做一次 240ms 的轻微上移和显现，之后不重复。
- 不使用持续动画、闪光、震动循环或切卡音效。
- 关注成功可以使用一次轻触觉反馈；每次滑动不振动。

## 7. 企业列表升级

### 7.1 目标

企业列表必须表现为高质量、可扫描的专业目录。V2.1 使用轻量独立卡片承载评分、总部与岗位方向，但不能恢复四周粗框、超大圆角和厚重按钮感。

### 7.2 工具区

- 页面标题和总数在同一结构中，但总数使用普通弱文本，不做独立圆角徽章。
- 搜索框高 48px、圆角 10px、1px 冷灰边框。
- 筛选 chips 高 36–40px、间距 8px；激活态为深墨底白字或浅橙底深橙字。
- 搜索和筛选区可固定在顶部栏下方；固定时使用实色背景和细分隔线。

### 7.3 企业列表卡片

- 页面背景为浅灰；单卡白底，卡间距 10–12px。
- 单卡最小高度约 116px，圆角 12px。
- Logo 56px，企业名 18–20px，元信息 14–15px，岗位摘要 14px。
- 关注按钮宽度 72–80px、高度 40–44px，圆角 8–10px。
- 企业名可两行，关注按钮不可侵占文本安全宽度。
- 第二信息层固定为行业与规模。
- 第三信息层按可用性展示 `总部 · 城市`、`★ 4.5`；不能用无来源星级装饰。
- 岗位摘要必须优先显示两个具体岗位方向，例如 `产品、前端可申请`。
- 卡片使用极浅边框或一层低强度阴影，二选一。
- 企业行点击进入企业详情，关注按钮独立。

### 7.4 与 Match 的共同语言

- 共用 `CompanyIdentity`：Logo、名称、行业、规模。
- 共用 `CompanyFollowAction`：图标、文案和状态。
- 共用岗位摘要格式。
- Match 使用 24px padding 和沉浸节奏；企业列表使用 16–20px padding 和高扫描效率。

## 8. 底部 Tab 修复

- Tab 总高度包含内容区和 `env(safe-area-inset-bottom)`。
- 背景必须延伸到屏幕底部，不能露出页面灰色或内容。
- 页面内容底部 padding 使用同一 CSS 变量，例如 `--tabbar-total-height`，禁止各页面手写不同数值。
- Match 图标可使用现有品牌资产，显示尺寸控制在 32–36px；两侧图标 22–26px，视觉比例约 1.35–1.45。
- Match 图标最多上移 4–6px，不能形成独立悬浮圆球覆盖卡组页码。
- 三个 Tab 的标签字号、基线和点击区域一致。
- 激活态通过橙色和字重表达，非激活态保持高可读灰色。

## 9. 跨页面一致性升级

### 9.1 必须建立的共享 tokens

- 页面背景和表面色。
- 文字三级颜色。
- 品牌橙三级颜色。
- 边框、圆角、阴影。
- 顶部栏高度和 Tab 总高度。
- 页面水平 gutter。
- 字号与行高。
- 按钮和触控目标高度。

### 9.2 必须共用的组件语言

- 顶部品牌栏。
- 底部 Tab。
- 企业身份。
- 关注状态。
- 搜索与 chips。
- 空状态、错误、骨架和重试。

### 9.3 不要求完全相同

- Match 可以低密度、强情绪、强层级。
- 企业列表可以中高密度、强扫描。
- 笔记可以内容优先、低装饰。
- 个人中心可以高功能密度。

一致性是共同的字体、颜色、组件和动作语义，不是所有页面都使用同一种卡片。

## 11. 状态与异常

- 加载：三层卡组骨架，保留页面标题位置，避免突然跳动。
- 有效缓存：正常展示；后台更新失败时使用非阻断横幅。
- 缓存过期：不展示为有效匹配，提供重新生成或重试。
- 空结果：`当前方向暂无合适企业` + `调整方向`。
- 严格条件空结果：指出可放宽的条件。
- Logo 失败：黑白首字回退。
- 关注失败：关注控件恢复原状态，Toast 说明重试。
- 权限拒绝：保留关注，提醒可稍后开启。
- 长企业名：最多两行，卡片高度允许小幅增长，不遮挡关注按钮。

## 12. 数据与接口要求

现有 `WatchFeedItem` 应至少支持：

- 企业 ID、名称、Logo、行业、规模。
- 总部地点、公开评分和评分来源。
- `score`、`scoreBreakdown`、`scoreConfidence` 和定性 `fitBand`。
- 一句压缩后的个人判断，或可生成该判断的结构化依据。
- 最多两个展示用匹配依据。
- 代表岗位 ID、岗位名、岗位元信息和最多两个 `openRoleLabels`。
- 相关岗位总数。
- 最近核验时间和结果有效期。
- 关注与提醒状态。

推荐响应建议新增：

```ts
scoreBreakdown: {
  direction: { score: number; max: 50; label: string }
  preferences: { score: number; max: 30; label: string }
  opportunity: { score: number; max: 20; label: string }
}
scoreConfidence: number
rating: number | null
ratingSource?: string
headquarters?: string
openRoleLabels: string[]
```

AI Coding 不得通过客户端任意拼接未经审核的大段推荐文案或计算第二套分数。服务端负责匹配度、覆盖度、事实字段和岗位方向；客户端只做有限格式化与缺失降级。

## 13. 埋点

保留并补齐：

- Match 结果页曝光。
- 卡片曝光和卡片停留时长。
- 匹配度点击、匹配依据 Sheet 展开和关闭。
- 左右滑动、回弹和切换完成。
- 企业详情打开。
- 代表岗位打开。
- 关注点击、成功、失败和取关。
- 首次手势提示是否完成。
- 从 Match 到官网、详情或关注的转化。

指标不只看关注率。核心诊断指标包括首张卡内容打开率、每次会话查看卡数、Match 到企业详情率、Match 到岗位详情率、关注率与 7 日回访率。

## 14. AI Coding 实施边界

### 必须修改

- Match 页面标题、方向摘要、卡片信息架构和样式。
- Match 服务端参考匹配度分解、数据覆盖度和事实字段响应。
- 卡片底部动作结构。
- 企业列表布局和关注按钮。
- Tab 安全区、尺寸和页面底部 padding。
- 小程序共享视觉 tokens。
- 相关文案和设计门禁测试。

### 保留

- 三 Tab 路由。
- Match 居中且适度强调的产品决策。
- 循环卡组和 14%/速度切换阈值。
- 关注与微信提醒解耦。
- 真实数据、有效期和缓存规则。
- 顶部头像进入个人中心。

### 不在本轮

- 重写核心岗位匹配引擎；本轮只校准 Career Watch 展示分数的可解释计算与响应字段。
- 重做会员定价与支付。
- 新增第四个 Tab。
- 引入第二套小程序组件库。
- 重做官网 UI。
- 使用虚构公司、岗位、评分或用户评价填充视觉稿。

## 15. 验收标准

### 产品

- 用户在 5 秒内知道这是个人 Match 结果，并知道卡片可滑动。
- 用户能快速理解企业与自己的关系和当前代表机会。
- 用户可以查看匹配度由哪些设置和事实构成，并理解它不是录用概率。
- 关注不是遮挡内容的唯一大按钮。
- 官网和小程序定位在所有有效文档中不再冲突。

### 视觉

- Match 卡片没有三层底部 CTA、AI 套话、超大空白或嵌套大卡。
- 企业列表评分、总部和岗位方向层级明确，仍保持轻、紧凑和统一。
- Tab 不遮挡内容，安全区背景完整。
- 黑白灰与橙色比例克制，页面明亮、现代且不疲劳。
