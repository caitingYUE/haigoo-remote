# Haigoo 小程序 Match 关注闭环设计规格

> 2026-09-02 supersession note: This document remains authoritative for the follow loop, reversible deck behavior, real-data requirements, cache validity, and separation of company follow from WeChat reminders. The current gesture threshold is 14% or a qualified fast swipe; the current visual and information direction follows `docs/superpowers/specs/2026-09-01-mini-match-immersive-v2-design.md` and `docs/haigoo-mini-design-system.md`.

- 日期：2026-09-01
- 状态：已完成对话评审，待书面规格复核
- 设计路径：Architectural
- 核心目标：帮助用户通过匹配工具发现感兴趣的企业，并持续关注其岗位动向

## 1. 背景与问题

小程序的基本链路已经跑通，但当前产品心智、导航结构和交互反馈仍不够成熟：Match 卡片主要依靠不透明分数表达推荐，企业关注入口存在图标语义不清，微信订阅授权与企业关注容易被理解为同一动作，个人中心占用一级 Tab，核心 Match 心智不够突出。

本次设计把产品从“展示匹配结果”调整为完整的关注闭环：

1. 用户设置求职方向。
2. Match 解释为什么推荐这些企业。
3. 用户浏览企业或岗位信息。
4. 用户明确关注感兴趣的企业。
5. 用户按需开启微信提醒，并可在个人中心回看岗位动态。

核心动作定义为：**使用匹配工具找到感兴趣的企业并关注其岗位动向。**

## 2. 成功标准

### 2.1 用户成功

- 用户能在单张卡片内理解“为什么适合我”“当前有什么机会”“信息是否新鲜”。
- 用户可以反复左右浏览固定的企业卡片，不因手势误触改变关注状态。
- 用户关注企业后，即使拒绝微信提醒，关注关系仍然保留。
- 用户能从头像入口回到个人中心，查看关注数量和未读岗位动态。

### 2.2 产品成功

- 北极星转化：看过匹配理由或企业详情的用户，至少关注一家企业。
- Match 成为中间一级入口和产品核心心智。
- 企业目录、Match、笔记形成清晰的“发现—决策—学习”三段结构。

### 2.3 上线成功

- 关键流程在游客、未绑定、免费、有效会员和过期会员状态下均可解释、可恢复。
- 微信开发者工具和真机中不存在导航失效、手势冲突、页面截断或关注状态错乱。
- 生产构建、体验检查、敏感信息复检和真机订阅消息验证全部通过。

## 3. 已选方案

本版本当时采用“解释型 Match + 温暖档案卡片 + 显式关注”的方案。其行为规则仍有效，但视觉与信息密度已经被 V2 规格替代：

- Match 先给出可解释的匹配理由，再引导查看企业与关注岗位动态。
- 不再实施本文件所述的“温暖档案”视觉；卡片结构、视觉和文案以 `docs/superpowers/specs/2026-09-01-mini-match-immersive-v2-design.md` 为准。
- 卡片以叠放卡组呈现，左右滑动只切换企业；关注和取关只由明确按钮触发。
- 企业关注与微信提醒解耦，避免将系统授权拒绝误判为业务失败。

不采用以下方案：

- 不使用纵向瀑布流作为 Match 主交互。
- 不使用滑动即关注或滑动即取关。
- 不继续用无法解释的匹配分数作为主要推荐依据。
- 不新增第四个底部 Tab。

## 4. 信息架构与导航

底部导航恢复为三个 Tab，并按下列顺序固定：

1. **企业**：企业目录，支持搜索、分类和筛选。
2. **Match**：居中显示，作为核心入口，复用现有专属图标。
3. **笔记**：职业学习与内容阅读。

实现约束：

- 现有路由继续复用：企业 `/pages/companies/index`、Match `/pages/index/index`、笔记 `/pages/growth/index`。
- `/pages/profile/index` 保留为普通页面，不再属于 `tabBar`；进入个人中心统一使用 `navigateTo`。从个人中心的子页面完成操作后优先 `navigateBack`，没有可返回页面时 `reLaunch` 到 Match。
- 三个一级页面统一显示品牌顶部栏和右上角头像。头像进入个人中心；存在未读岗位动态时，头像显示数量徽标。
- 个人中心中的企业关注数、未读岗位动态和求职方向仍可返回对应一级页面。
- 中间 Match 项使用现有 `/miniprogram/assets/icons/match.svg` 与 `/miniprogram/assets/icons/match-active.svg`，不重新绘制或用通用目标图标替代。
- 本规格中的三 Tab 结构取代 `docs/haigoo-mini-design-system.md` 第 4 节所记录的旧四 Tab 结构；实施时必须同步更新该文档，避免两套导航规范并存。

## 5. Match 页面结构

Match 页按以下层级组织：

1. 顶部品牌栏与个人头像。
2. 标题“为你匹配的企业”，并用一句短文案解释结果来源。
3. 企业叠放卡组。
4. 当前序号和轻量手势提示。
5. 必要的刷新、空状态或错误恢复入口。

一屏只保留一个视觉主操作：当前卡片的“关注岗位动态”。“查看企业”作为次级文字动作，不与主按钮竞争。

### 5.1 单张卡片信息顺序

- 企业标识、企业名称、行业和团队规模。
- 两至三个可解释的匹配理由，例如岗位方向、团队偏好和行业偏好。
- 当前开放岗位数量与一个代表岗位。
- 最近核验时间。
- 一句克制的推荐语，用于提供编辑感和情绪满足，不替代事实信息。
- 主操作“关注岗位动态”或状态“已关注”。
- 次操作“查看企业”。

不显示无法解释的 85、90 等数值分数。若后端仍需要分数排序，分数只作为内部排序信号，不直接呈现给用户。

## 6. 叠放卡组交互

视觉参考为用户提供的卡组截图：

`/var/folders/31/06qzndgs1cbb3kw9z360dtq80000gn/T/codex-clipboard-92bfde7c-b345-4718-b2f0-a05d9e64c261.png`

交互规则：

- 前景卡完整展示；后方最多露出三张卡，通过轻微位移、缩放和旋转表达层级。
- 用户可向左或向右拖动切换企业，卡组首尾循环，可反复返回已看卡片。
- 松手时水平位移达到卡片宽度的 14% 完成切换；快速轻扫在位移达到 24px 后可按速度触发，不足阈值自动回弹。
- 手指移动达到系统可识别的水平拖动后才接管卡片，优先避免与页面纵向滚动冲突。
- 点击“关注岗位动态”“已关注”“查看企业”或岗位入口时不得触发滑动。
- 左右滑动只修改当前卡片索引，不修改关注状态、不申请微信权限。
- 当前固定快照的活跃索引保存在本地；同一快照再次进入时回到上次位置。快照版本变化后从第一张开始。
- 用户开启“减弱动态效果”时，取消卡片旋转和弹性过渡，仅保留短距离平移与淡入淡出。

视觉约束：

- 沿用品牌橙 `#E65A20`、主文字 `#161A22` 和温暖浅色表面，不引入新的高饱和主色。
- 深色只用于档案式卡片顶部，不扩展为整页深色背景。
- 卡片圆角、留白和阴影遵循现有小程序设计系统；阴影只用于表达叠放关系。
- 企业 Logo 使用真实资源；Logo 缺失时显示企业名称首字，不使用占位图或虚构图标。

## 7. 关注与提醒状态机

### 7.1 关注

1. 未关注时，主按钮显示“关注岗位动态”。
2. 点击后先调用关注接口；提交期间禁用重复操作并显示进行中状态。
3. 后端确认成功后，按钮更新为“已关注”，并提供轻量成功反馈。
4. 关注成功后再单独询问是否开启微信提醒。
5. 接口失败时保持未关注状态，并提示原因和“重试”。

### 7.2 微信提醒

- 微信提醒是关注后的可选增强能力，不是关注成功的前置条件。
- 用户接受授权后更新提醒状态；用户拒绝、取消或系统不可用时，企业关注关系不回滚。
- 已拒绝时不连续打扰；仅在用户主动进入提醒设置或合理的后续场景再次提供入口。

### 7.3 取关

- 点击“已关注”进入轻量确认：“取消关注后，将不再在关注动态中展示这家企业的新岗位。是否继续？”
- 确认后调用取关接口；成功才更新卡片状态和个人中心数量。
- 取消确认或接口失败均保持原关注状态。

## 8. 数据契约与真实性

每张 Match 卡片需要来自真实接口的数据：

- 企业 ID、名称、Logo、行业、团队规模。
- 两至三个匹配理由，理由必须可追溯到用户求职方向或企业事实。
- 当前开放岗位数量、代表岗位 ID 与岗位名称。
- 企业或岗位最近核验时间。
- 当前关注状态和微信提醒状态。
- 所属匹配快照 ID 或版本，用于稳定顺序和位置恢复。
- 服务端提供的 `verifiedAt`、`validUntil` 和有效状态，用于判断卡片是否仍可展示。

结果规则：

- 免费固定快照必须稳定返回五家有效企业；顺序在同一快照内不因重新进入页面而变化。服务端若无法凑齐五家有效结果，应将快照判为不可发布并返回可恢复错误，不得用虚构数据或已失效企业补足。
- 只有后端确认仍有有效公开岗位的企业才能标记“正在招聘”或进入当前 Match 卡组。
- 过期岗位、无法确认有效性的岗位或长期未核验数据不得继续显示为“在招”。
- 匹配理由为空时不拼装虚假理由；该结果应由服务端剔除或降级为可验证的企业事实。
- 关注接口和微信提醒接口保持独立；现有 `followCompany`、`unfollowCompany`、`setMatchNotifications` 能力继续复用。

## 9. 加载、异常与空状态

- **首次加载**：展示与三层卡组轮廓一致的骨架屏，避免普通列表骨架造成布局跳变。
- **刷新失败且有缓存**：只有缓存快照尚未超过服务端 `validUntil` 时才继续展示，并标注“暂时无法更新，正在展示上次结果”，同时提供重试。
- **刷新失败且无缓存**：显示完整错误状态、简明原因和“重新加载”。
- **缓存已经过期**：按无可用缓存处理，不继续展示招聘状态。
- **没有结果**：解释为当前方向暂无合适企业，并提供“调整求职方向”。
- **严格筛选无结果**：明确提示放宽某项条件，不笼统显示“暂无数据”。
- **Logo 加载失败**：回退为企业名称首字，不影响卡片与操作。
- **关注失败**：保留原状态，错误靠近按钮呈现，同时允许重试。
- **信息过期**：从卡组中移除，不以旧缓存继续标记为在招。

## 10. 企业目录与个人中心联动

### 10.1 企业目录

- 保留搜索、行业和分类筛选能力。
- 列表中的图标式“+”改成明确的“关注”或“已关注”文字按钮。
- 企业目录与 Match 共用同一关注状态来源；任一页面操作后，另一页面重新显示时必须同步。
- 目录中的岗位状态同样受最近核验时间约束。

### 10.2 个人中心

- 个人中心从右上角头像进入，不占用底部 Tab。
- 未读岗位更新徽标从原“我的”Tab 转移到头像。
- 个人中心继续展示关注企业数和未读岗位更新数，并能进入相应页面。
- 从个人中心返回时优先回到用户进入前的一级页面，不强制跳转 Match。

## 11. 组件边界

- `MatchCompanyDeck`：只负责手势、索引、循环、叠放布局、位置恢复和减弱动画。
- `MatchCompanyCard`：只负责单家企业的档案式信息展示和可访问标签。
- `CompanyFollowAction`：统一关注、取关确认、提交状态、失败恢复和跨页面状态通知。
- `WechatReminderAction`：独立处理微信订阅授权和提醒状态，不控制关注关系。
- `EditorialTopBar`：扩展为三个一级页面共用的品牌栏、头像入口与未读徽标。
- `CustomTabBar`：只保留企业、Match、笔记三个入口，并使用专属 Match 图标。

组件通过明确的企业数据和事件回调交互，不把请求、权限申请和卡片手势集中在一个大组件内。只对本次涉及的现有页面做必要拆分，不进行无关重构。

## 12. 埋点与评估

至少记录以下事件：

- Match 卡组曝光。
- 单张企业卡曝光。
- 左滑、右滑及切换后的卡片索引。
- 查看企业详情和查看岗位。
- 关注点击、成功、失败。
- 取关请求、确认、取消、成功、失败。
- 微信提醒提示、接受、拒绝和不可用。

评估口径：

- 主指标：Match 有效访问用户中，关注至少一家企业的用户比例。
- 诊断指标：看过匹配理由、打开企业详情后完成关注的比例。
- 质量指标：关注接口失败率、卡片手势取消率、提醒拒绝后关注异常回滚数。
- 不把微信提醒接受率作为关注成功率，二者分别统计。

## 13. 可访问性与体验要求

- 所有主要触控区域不小于 `88rpx`，相邻操作保留足够间距。
- 关注、已关注、查看企业、头像和 Tab 均提供明确的读屏名称与状态。
- 不单独依赖颜色区分关注状态；状态同时使用文字和图标。
- 页面适配顶部胶囊区域、底部安全区和小屏高度。
- 动画不阻塞操作，加载和提交状态避免重复点击。
- 中文承担全部任务信息，英文只作为品牌辅助。

## 14. 测试与发布验收

### 14.1 功能与交互

- 固定快照稳定展示五张卡。
- 卡片可向左、向右循环，能回到已看卡片。
- 14%/速度切换阈值、未达阈值回弹和纵向滚动无冲突。
- 卡片内按钮点击不会触发滑动。
- 关注成功、失败、重复点击保护和跨页面同步正确。
- 取关确认、取消、失败和成功状态正确。
- 用户拒绝微信提醒后，关注状态仍为“已关注”。
- 三个 Tab 路由正确；头像进入个人中心，返回行为正确。
- 加载、缓存降级、完整错误、空结果、严格筛选和 Logo 失败状态完整。
- 过期或未核验岗位不再显示为“在招”。

### 14.2 身份与权限

- 覆盖游客、未绑定、免费、有效会员和过期会员。
- 未登录或未绑定用户触发需要身份的动作时，说明原因并能完成后续返回。
- 免费固定五家与会员动态能力的边界清晰，不出现错误会员文案。

### 14.3 视觉与设备

- 在小屏设备、iPhone 12/13 尺寸和大屏设备中检查叠放层级、按钮、安全区和内容截断。
- 开启减弱动画后验证卡片切换。
- 微信开发者工具和至少一台真机完成关键流程截图对比。
- 与 V2 视觉参考 `artifacts/miniprogram-match-v2-reference/match-v2-reference.png` 进行同视口对照，不以单张截图代替差异检查。

### 14.4 工程与上线门禁

- TypeScript 检查通过。
- 小程序体验检查与生产构建检查通过。
- 最大静态资源、分包和主包大小在微信限制内。
- 微信开发者工具重新执行敏感信息与隐私合规检查。
- 真机验证关注接口、微信订阅消息授权、拒绝授权和消息到达。
- 确认生产环境没有测试企业、失效岗位、虚假核验时间或硬编码密钥。

## 15. 上线阻断项与范围外事项

本期不顺带重做会员定价、支付商品或服务套餐。但当前会员页将订阅权益与服务混合展示、默认推荐半年方案的决策，与既有“订阅和服务分开”的上市策略存在冲突。该问题必须在正式上线前由产品负责人明确选择并完成复核；在结论产生前，整体上线状态保持“有条件通过”。

此外，本期不包含：

- 新增第四个底部 Tab。
- 滑动即关注或滑动即取关。
- 新建另一套组件库。
- 无关的服务端重构或会员业务重写。
- 用虚构分数、虚构企业信息或未核验岗位填满五张卡。
