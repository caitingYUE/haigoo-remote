# Haigoo Remote 第二轮中文 UX 本地化审计

日期：2026-08-12  
阶段：审计完成，尚未进入实现

## 1. 结论

当前版本的视觉升级是成功的。暖象牙色、深墨蓝、克制紫色、衬线标题、细分隔线和海边自然光共同形成了清晰的 Haigoo 识别度，不应推翻，也不应回到卡片密集的 SaaS 风格。

本轮真正需要解决的不是审美，而是使用频率：页面更像适合阅读和展示的数字杂志，还没有完全成为华语用户每周都能顺手使用的职业产品。

建议方向：

> 保留首页和职业成长的编辑感；在岗位、企业和个人工作台中增加中文优先级、信息密度、动作可见性与真实的活跃信号。

## 2. 审计依据

已检查：

- 当前本地实现：`/`、`/jobs`、`/trusted-companies`、`/careerlearning`、`/profile?tab=resume`、`/profile?tab=membership`
- 桌面视口：1440 × 900
- 移动与平板视口：375 × 812、390 × 844、430 × 900、768 × 1024
- 当前升级截图：
  - `artifacts/brand-upgrade-phase2/15-final-home-1440.png`
  - `artifacts/brand-upgrade-followup/after/jobs-desktop-v2.png`
  - `artifacts/brand-upgrade-companies/after/companies-desktop.png`
  - `artifacts/brand-upgrade-playback-profile/after/profile-desktop.png`
  - `artifacts/brand-upgrade-playback-profile/after/watch-desktop.png`

量化观察：

| 页面 | 当前状态 | UX 影响 |
| --- | --- | --- |
| 岗位列表 desktop | 单行约 135px，1440 × 900 可见约 5 行 | 基本可用，但仍偏展示型；压缩至约 100–112px 后可稳定看到 6–7 行 |
| 远程企业 desktop | 第一张企业内容约在 1169px 才出现 | 900px 首屏完全看不到企业，产品任务被品牌说明推迟 |
| 远程企业 mobile | 第一张企业内容约在 1458–1497px 出现 | 用户需要滚动约 1.7 屏才进入企业浏览 |
| 首页 mobile | 最近岗位标题约在 1541px，第一条岗位约在 1795px | 搜索之后仍需经过品牌图和承诺区，岗位进入过晚 |
| 岗位 mobile | 筛选按钮为普通相对定位，不吸附 | 浏览较长列表后修改筛选需要回到顶部 |
| 我的 mobile | 标题约 41–47px，顶部标签栏只显出前四项 | 个性化信息存在，但账户导航和大标题抢占了功能空间 |

所有抽查视口均未出现横向页面溢出，这是当前响应式实现的优点，应继续保持。

## 3. 全站问题

### P0 — 中文没有稳定成为第一信息层

以下英文标签目前仍处于视觉第一顺位：

- `HAIGOO FIELD NOTES · 职业成长`
- `COMPANY NOTES`
- `WATCHING`
- `MY HAIGOO · 个人工作台`
- `SAVED`
- `HAIGOO CAREER CONSULTING`
- `REAL MOMENTS`
- `WHAT REMAINS`
- `SERVICE CAPABILITIES`
- `BEFORE YOU START`
- `REMOTE COMPANY INDEX · 远程企业`
- `RECENTLY UPDATED · 最近更新`

这不会造成语言理解失败，但会持续传达“欧美网站中文版”的距离感。建议统一成“中文主标签 + 英文小注”：

| 当前 | 建议 |
| --- | --- |
| `Recently updated` | `最近更新 · Recently updated` |
| `Career journal` | `职业成长 · Career journal` |
| `Remote companies` | `远程企业 · Remote companies` |
| `Open community` | `开放交流 · Open community` |
| `REMOTE COMPANY INDEX · 远程企业` | `远程企业 · Remote company index` |
| `HAIGOO FIELD NOTES · 职业成长` | `职业成长 · Haigoo field notes` |
| `COMPANY NOTES` | `企业观察 · Company notes` |
| `WATCHING` | `正在观看 · Watching` |
| `MY HAIGOO · 个人工作台` | `我的 Haigoo · 个人工作台` |
| `SAVED` | `我的收藏 · Saved` |
| `REAL MOMENTS` | `最近大家常来聊这些 · Common questions` |

企业名、岗位原始标题、视频标题等来源内容可以保留英文；`Remote in China` 等界面元数据在中文环境中应标准化为“中国远程”。

### P0 — 动作语义有一处明显错位

岗位列表每行显示“官网直达”，但点击整行实际是打开右侧岗位详情，而不是直接离开网站前往官网。这会让用户误判点击结果。

建议：

- 列表尾部：`查看岗位 →`
- 详情主按钮：继续保留 `官网直申`
- 企业来源链接：`前往企业官网 ↗`

首页搜索和企业搜索目前都以圆形箭头作为主要视觉按钮，虽然有 ARIA 标签，但视觉上仍需要用户猜测。建议显示明确的“搜索”动词；通知、菜单、分页等约定俗成的工具图标可以继续只显示图标。

### P0 — 页面密度没有按任务分层

当前页面共享了过于一致的编辑型留白：

- 首页 Hero：密度正确，应保留。
- 职业成长：密度正确，应保留。
- 岗位页：应增加约 25–30%。
- 企业页：应增加约 20%。
- 我的 Haigoo：应增加约 25–30%。
- 咨询页：视觉密度可以保留，但语言结构应更口语化。

不要全局缩小 spacing token；应使用页面级 density token 或组件变体。

### P1 — 活跃信号存在，但没有形成稳定语言

现有真实数据已经可以支持：

- 岗位总数与 `updatedAt / publishedAt`
- 企业 `updatedAt` 与公开岗位总数
- 职业成长的真实视频总数
- 用户收藏数、申请记录数
- 视频跟读片段及时间范围

当前职业成长已经显示真实视频总数，企业页也显示实际更新时间，这是正确方向。首页只加载最近 6 条岗位，不适合直接用这 6 条推断“今天更新总数”。首页可优先使用接口返回的真实岗位总数，或显示最近一条真实更新时间；没有全量日期聚合前不要写“今天更新 N 个”。

### P1 — 语义结构仍有可访问性残留

岗位页当前由岗位详情标题承担 H1，而“远程工作”是 H2；移动端隐藏详情后页面可能没有可见 H1。同时页面存在全局 `main`、岗位页 `role=main` 和详情内部 `main` 的重复地标。

建议在实现阶段统一：

- 页面 H1：远程工作
- 嵌入式岗位详情标题：H2
- 独立岗位详情页标题：H1
- 每个页面只保留一个主 `main` 地标

## 4. 分页面审计

### 4.1 首页

保留：

- 当前 Hero 构图、品牌标题、自然光图片和承诺条。
- 搜索是唯一主动作。

需要调整：

1. 移动端最近岗位标题在约 1541px，第一条岗位在约 1795px，进入内容过晚。
2. 分类横向区域在 375–390px 下需要滚动，但末端缺少明显的可滚动提示。
3. Hero 搜索按钮仅显示箭头。
4. 品牌卡底部 `PUBLIC SOURCE / UPDATED / DIRECT APPLY` 应改为中文主标签。

建议：

- Desktop 基本不动。
- Mobile 将右侧品牌图片卡移到最近岗位之后，或压缩成较矮的品牌注记。
- 承诺条在移动端改成紧凑三行，不增加新卡片。
- 搜索附近增加一个真实小信号，如“当前可浏览 N 个远程岗位”；必须使用接口真实总数。
- 分类选中态使用暖灰底、细下划线或低饱和紫色，不使用高饱和填充。

### 4.2 远程岗位

当前优点：

- 已使用单一页面滚动。
- 行式结构和分隔线方向正确。
- 详情主按钮清晰，未产生付费或推荐表达。

主要问题：

1. 单行约 135px，实际首屏约 5 行；目标应为 6–7 行。
2. 标题、公司、地点、技能与更新时间仍分散，扫描路径较长。
3. 列表动作写“官网直达”，但点击行为是查看详情。
4. `Remote in China` 等地点没有按中文 locale 标准化。
5. “一月前”不够自然，也缺少“更新”语义。
6. 移动筛选不是 sticky，且三个独立下拉并非最适合手机的筛选方式。

建议默认行信息：

```text
无界方舟
AI Product Manager
产品 · 全职      中国远程 · 英文工作
更新于 1 个月前 · 企业官网                 查看岗位 →
```

语言、薪资、摘要和次要标签进入详情或展开层。保留 editorial divider，不改成卡片。

移动端建议：

- `默认 / 收藏 / 申请中` 保留紧凑切换。
- 筛选改成吸附工具条，显示“筛选”及当前已选数量。
- 角色、地点、更多条件进入底部抽屉。
- 每行始终显示“查看岗位”，不依赖 hover。

### 4.3 远程企业

当前优点：

- 企业内容的编辑型表达成熟。
- 真实更新时间、公开岗位数和企业来源均可支撑持续运营感。

主要问题：

1. Desktop 第一张企业在约 1169px；Mobile 在约 1458–1497px。
2. Hero、三项说明、搜索、整理说明依次展开，实用内容被推迟。
3. 当前可用筛选只有行业和岗位方向；附件建议的地域/团队类型尚未在现有数据中确认。

建议：

- Hero 缩短约 15–20%，但保留大标题。
- 搜索与筛选紧接 Hero；“我们如何整理信息”折叠为二级说明。
- 首屏尽量露出第一条企业内容。
- 第一阶段只使用真实支持的筛选：全部、行业、岗位方向。
- 排序可提供“最近更新 / 企业名称”；名称与更新时间均有真实字段。
- 全球远程、APAC、亚洲团队等筛选在数据字段确认前不展示。

### 4.4 职业成长

这是最适合保留杂志式空间的页面，不建议提高整体密度。

需要调整：

- 将 `HAIGOO FIELD NOTES` 降为中文标题后的英文小注。
- 内容卡上的 `Free` 在中文界面可改为“开放观看”；历史 `Club` 身份可以保留。
- 当前真实视频总数是合适的 life signal。

“继续上次学习”目前没有发现通用视频播放历史或播放进度数据。现有 `job_bundle_user_progress` 仅服务岗位合集，不能冒充全站观看历史。因此：

- 本轮可以继续中性展示最近更新内容。
- 若未来允许新增真实观看记录，再增加“继续上次学习”；不应先做假进度 UI。

### 4.5 我的 Haigoo

当前已经比旧版更个人化：打开后可看到问候、收藏数量和申请数量，方向正确。

仍需改善：

1. `MY HAIGOO` 和 `SAVED` 仍让英文处于第一信息层。
2. Mobile 问候标题约 41–47px，个人数据进入稍慢。
3. “职业成长”目前是泛化的“继续阅读”，没有真实最近观看记录支撑。
4. Mobile 顶部标签栏只显出首页、咨询、关于、反馈，账户设置依赖横向滚动且缺少提示。
5. 收藏与申请有真实最近记录，但首页摘要只显示数字，没有把“Haigoo 记得我”表达出来。

建议：

- 问候副标题改为：“最近看过的机会和内容，都帮你留在这里了。”
- Desktop 首屏直接显示最近 2–3 条收藏和最近 2–3 条申请，而不是只有数字入口。
- Mobile 将问候缩到 36–40px，并让第一条个人记录更早出现。
- 没有真实观看历史时，“最近在看”显示最近收藏的职业成长内容；仍无数据则使用自然空状态，不显示假进度。
- 历史 Club Member 增加克制的状态区；普通用户不显示 Free User、升级或定价。

### 4.6 咨询服务

当前合规边界和视觉克制都正确，但页面仍偏工作室提案：六组英文眉题、两组编号内容和能力清单共同产生了距离感。

建议：

- 保留主标题“职业卡住的时候，先把问题说清楚”。
- `REAL MOMENTS` 改为“最近大家常来聊这些：”。
- 使用附件提供的四类概括场景，不写成客户证言。
- 增加：“你不需要提前想清楚问题，带着现在的困惑来就可以。”
- 去掉故事卡和服务能力中的重复序号，只在真正有顺序的咨询过程里使用编号。
- CTA 保留“说说你现在的问题 →”。
- “不展示价格，也不会自动下单”偏系统与交易语言，可改为：“先聊聊现在的问题，再确认是否适合继续。”

### 4.7 视频与内容详情

当前双栏结构成熟，视频与企业观察的关系清楚。

需要调整：

- `WATCHING` → `正在观看 · Watching`
- `COMPANY NOTES` → `企业观察 · Company notes`
- 右侧标签应表达“边看边用的工具”，而不是独立资料库。

现有跟读片段已经包含时间范围，可支持“本期你会听到”的章节目录。点击时间跳播需要先确认当前 Bilibili iframe 与其他视频源是否提供统一 seek 接口；在播放器适配未确认前，不应展示不能工作的时间跳转。

## 5. 低饱和语义色建议

只用于数据扫描，不用于装饰：

| 状态 | 建议语义 | 使用位置 |
| --- | --- | --- |
| 全球远程 | 极浅雾蓝 | 岗位地点元数据 |
| 中国远程 | 极浅鼠尾草绿 | 岗位地点元数据 |
| APAC | 极浅薰衣草 | 仅在真实地域字段存在时 |
| 最近更新 | 极浅暖黄 | 24–72 小时内真实更新 |
| 自由职业 | 暖中性色 | 岗位类型 |

所有状态仍需文字说明，不能只靠颜色。

## 6. 实施优先级

### 第一批：高收益、低业务风险

1. 中文主标签、英文小注的全站替换。
2. 岗位列表动作从“官网直达”改为“查看岗位”。
3. 中文地点与更新时间标准化。
4. 首页和企业搜索按钮显示中文动词。
5. 修正岗位页 H1 和重复 main 地标。

### 第二批：密度与移动路径

1. 岗位行压缩至 6–7 行 / desktop 首屏。
2. Mobile sticky 筛选与底部抽屉。
3. Mobile 首页让最近岗位提前出现。
4. 企业搜索提前，整理说明渐进披露。

### 第三批：个人感与内容工具

1. 我的 Haigoo 首屏显示最近收藏和申请。
2. 咨询页改成更自然的对话语言。
3. 视频章节与时间跳转可行性验证。
4. 低饱和状态色与微交互统一。

## 7. 不应改变的内容

- 暖象牙色、深墨蓝、克制紫色和当前字体体系。
- 首页 Hero 的核心构图与品牌主标题。
- 职业成长的编辑型阅读密度。
- 岗位全部开放、客观排序、企业官网申请的合规模式。
- 历史会员真实权益与身份。
- 收藏、申请记录、认证、数据结构和现有业务判断。

## 8. 审计门结论

建议进入实施，但必须按页面密度分层推进，不能做全站统一缩放。第一版实现应优先处理中文信息层、岗位扫描和移动内容顺序，再检查是否仍保持 Haigoo 的高级编辑感。

本审计阶段未修改页面代码。
