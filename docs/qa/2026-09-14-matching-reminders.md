# 企业匹配更新提醒与长期订阅核实

用户要求：订阅后持续关注匹配更新；仅当所关注企业的新岗位符合用户自定义设置或简历中确认的岗位类型时提醒。入口改为“订阅匹配更新”，提示“企业有匹配的岗位时提醒你”。

## 微信长期订阅的实际核实

2026-09-14 使用微信官方接口 `gettemplate`、`getcategory`、`getpubtemplatetitles` 读取本小程序当前权限，分页遍历全部可用类目模板。只读查询，没有添加模板、修改类目或发送通知。[原始摘要](2026-09-14-wechat-long-subscription.json)

- 当前私有模板“新职位更新提醒”：`type=2`，一次性订阅。
- 当前类目：信息资讯（1363）、信息查询（612）。
- 分别读取 251、1,269 条公共模板，共 1,520 条；接口返回类型 2 和 4，未返回长期订阅的类型 3。不能将未经核实的类型 4 当作长期许可。
- 结论：当前账号可用模板中没有可直接选用的长期订阅模板，不能通过修改按钮或重复调用发送接口获得长期发送权限。

微信一次性授权与额度规则见 [腾讯云 CloudBase 小程序订阅消息说明](https://docs.cloudbase.net/recipes/add-subscribe-message-cloud-function)。账号实际权限以本次微信 API 返回为准；官方微信文档页面在当前研究工具中无法直接打开，未将社区帖子中的旧类目列表当成当前申请承诺。

## 如何继续申请长期能力

在微信公众平台的“订阅消息 → 公共模板库”核对是否提供与实际业务相符的长期模板。若没有，需要向微信官方支持核实“用户订阅的企业出现匹配求职岗位”场景是否开放，以及主体、服务类目和资质要求。获得相符的长期模板后，确认 API 返回 `type=3`，再接入长期授权的保留/取消逻辑。不能仅为消息权限改成与实际业务不符的类目，也不能承诺更换类目必然获批。

可提交给官方支持的咨询内容（仅备稿，未发送）：

> 小程序 AppID：wxc61db5b8b472925a。当前订阅消息类目为信息资讯、信息查询。业务场景：用户主动关注远程企业并保存求职岗位类型；仅当该企业出现与岗位偏好匹配的新职位时发送服务提醒，用户可随时取消。现有模板为“新职位更新提醒”，字段包括招聘企业名称、职位名称、工作地点、工作类型、更新时间。请确认此场景能否申请长期订阅，所需主体资质、服务类目与申请入口，以及是否有可用长期模板。

在获得长期资格之前，企业关注与应用内匹配动态可持续保留，微信外部通知仍受一次性授权限制。此次没有新增邮件或公众号通道，没有声称已开通长期订阅。

## 1.0.40 修复

- 生成提醒收件箱和领取发送任务时，都使用同一 SQL 匹配函数，要求有效的已保存 Match 岗位偏好。
- 岗位类型从岗位标题和分类识别，不从描述里提到的其他团队扩展，防止例如后端职位提到设计团队就触发设计提醒。
- 自定义、简历、混合来源均检查岗位方向；保存了具体岗位类型时，还必须匹配具体词。关键词使用文字匹配，`%`、`_` 不会变成 SQL 通配符。
- 不匹配、偏好缺失或暂停时不发送；不会消耗用户微信授权。排队期间修改偏好、删除偏好或修改岗位标题/分类时，发送前再次拦截。
- 新增迁移 090，只新增匹配函数并更新可发送视图；不修改旧迁移 089、不删除关注或授权，不回放历史职位。
- 前端所有企业提醒入口复用同一说明和偏好检查；未设置时引导进入 Match。按钮为“订阅匹配更新”，授权成功提示“企业有匹配的岗位时提醒你”。授权说明明确当前每次授权只可接收一条，避免暗示已获得永久微信权限。
- 本地 22 组后端隔离回归通过，涵盖真实 SQL 与模拟微信；客户端覆盖偏好缺失、取消弹窗、重复点击、账号切换和静默状态同步。没有真实消息测试。

## 发布边界

本次新需求对应 **1.0.40**；已上传的 production 1.0.39 不包含这些修正，不应把其视为满足本次新需求的候选。先完成 1.0.40 体验环境迁移、后端更新与上传，再验收新交互。
