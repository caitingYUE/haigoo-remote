# 爬虫与失效检查修复验收（2026-09-28）

## 实际问题与修复

预发记录表明：Braintrust 首次请求失败导致任务暂停，另外 19 家处于等待状态，并不是 20 家均执行失败。旧界面提供的「继续检查」不能恢复失败企业，形成操作死路。

| 问题 | 修复后的行为 |
|---|---|
| 失败后继续按钮无法恢复任务 | 显示「重试本家（n/5）」和「跳过并检查下一家」；通用继续按钮不能绕过重试计数 |
| 整站完整性阻止有效样本通过预检 | 最多展示 5 条完整样本；归属和字段有效才可人工通过；明确样本成功不等于全站读取完成 |
| 招聘列表失败后停止所有检查 | 已通过企业仍独立逐条验证已发布岗位；保留列表失败和部分完成提示 |
| Pinpoint JSON 被当作 HTML | 正确提取 Meliore 的标题、正文、职责、要求、福利、地点和工作类型 |
| 漏识别详情或误读人才库加入页 | 支持 /job/、/vacancies/，排除 join/search；只跟随实际同站招聘入口，不猜测 URL |
| ATS 动态详情或 URL 名称变化 | Lever、Greenhouse、SmartRecruiters 优先按稳定岗位 ID 查询官方公开详情接口 |
| 主视窗堆满脚本 | 默认展示可读正文或接口岗位字段；完整响应收进技术详情，内容不执行 |
| 专属招聘域名/中文企业名不匹配 | 认可匹配 ATS 企业标识、YC 企业专属路径、已有唯一归属招聘域名；保留跨企业拦截 |

## 需求核对

- 两个入口「爬虫预检」「更新检查」，锁定点击时的当前页企业。
- 预检不改变岗位；人工通过只授予资格。首轮之外最多 5 次人工重试，次数耗尽不自动判定。
- 更新仅处理人工批准、来源版本未变化的企业，提取新增和变更，并逐条检查已有已发布岗位。
- 新增可编辑并保存为真实待审核岗位；保存已有修改草稿时保留线上旧内容。发布、转待审核、删除与恢复均需人工决定。
- 超时、403、429、5xx、跳转和无法匹配身份判为无法确定。空列表不能推导已有岗位失效。软删除可恢复。
- 不恢复定时抓取、定时链接巡检或自动下线，保留企业元数据、人工分类和权限。
