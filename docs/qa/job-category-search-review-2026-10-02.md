# 可信企业岗位分类搜索验收 · 2026-10-02

## 需求与现状

入口：可信企业 → 在招岗位/待审核岗位 → 编辑职位信息 → 岗位分类。`AdminCompanyJobsModal` 使用共用 `EditJobModal`，该组件已包含搜索框和 `rankJobCategories`，此前未完成交互验收。用户截图仍为原生长下拉列表，不能据此确认当时加载的代码版本。

本次保留现有单选分类及人工保存流程；不会创建新分类，不会搜索即保存，不改动岗位内容或状态。

## Review 发现与修复

1. 搜索框没有拦截 Enter，可能触发表单提交；缺少方向键选择、焦点返回及明确的无结果反馈。现支持上下键移动、Enter 选择、Escape 取消、Tab/点击外部关闭；输入法组词期间不执行选项选择。
2. 匹配逻辑只要命中一个分词就返回结果，短别名如 `ai` 可能误命中 `chair`。现按精确、前缀、包含、忽略分隔符、别名、多关键词、中文有序片段依次排序；多关键词须全部满足，短英文别名按完整词匹配。模糊匹配不承诺任意拼写纠错或拼音搜索。
3. 新增产品设计、用户研究、测试及算法的常用别名，保留当前分类配置。例：`用户调研` → `用户研究`，`backend` → `后端开发`，`产经` → `产品经理`，`UI UX` → `UI/UX设计`。
4. 切换岗位、取消或关闭下拉框时清空搜索；保留岗位原有历史分类，只有显式选择选项才修改当前表单值。
5. 企业岗位列表原来在配置尚未载入或失败时只传入 11 个硬编码分类，覆盖了编辑器完整兜底。现复用共享的 69 个标准分类兜底。

## 验证

- `npm run test:job-category-search`：精确优先、中文部分/有序片段、英文别名、大小写/全角、分隔符、多个关键词、无结果、重复选项与历史值。
- `npm run type-check` 通过；发布脚本包含本测试及构建回归。
- 使用浏览器运行真实 `EditJobModal`（本地虚构岗位，不连接数据库），确认：
  - `UI UX` 只显示 UI/UX设计，Enter 后分类改变而保存回调未执行。
  - 无结果显示提示，Enter 不保存也不改原分类。
  - Escape 关闭后焦点返回分类按钮；重新展开搜索为空。
  - Tab 关闭菜单并移至下一表单项（首页精选展示）；列表容器显式退出 Tab 顺序，避免浏览器把可滚动列表作为额外焦点站点。
  - 搜索“设计”，精确的“设计”排第一；方向键移动与 Enter 选择正确。
  - 点击保存后回调得到正式分类 `产品设计`，岗位标题保持不变。
  - 带搜索切换到下一条后菜单关闭；重新打开保留 `历史分类`，完整分类与空搜索正常。
  - 鼠标点击“用户研究”可选中；下拉框在较窄的实际视窗中仍可滚动与搜索。
- 浏览器截图：`.impeccable/review/category-search-accepted.png`（本地验收图，并非预发截图）。
