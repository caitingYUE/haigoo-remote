## 发送语义与限制

一次授权预约下一次上新通知，不承诺无限期自动推送；收到后用户可再次授权。单个用户同时关注企业并订阅方向时，同一上新只生成一条收件箱记录，优先使用有效企业授权。

微信明确拒绝且属于临时错误时可重试。发送超时、响应不完整、发送后的进程中断则记为 `unknown`，禁止自动重发，因为消息可能已经发出。相关旧授权会保守清除，避免再次消耗；新授权通过版本检查保留。管理员可以按 `last_error`、`attempt_count`、`attempt_id`、`wechat_message_id` 追查；`unknown` 需要人工核实，不能直接改回 pending。

`sent` 仅表示微信 API 明确接受，不表示设备已收到或用户已阅读。已进入网络发送过程的消息不能承诺因随后取关而撤回。定时消费采用单数据库串行租约，330 秒租约大于当前 Vercel 300 秒执行上限；每轮只在前 200 秒预算内开始发送，避免续跑相互重叠。后续若吞吐不足，再按实际积压量拆分消费者；本次未增加独立队列基础设施。

错误处理依据参考 [腾讯云订阅消息错误码说明](https://intl.cloud.tencent.com/document/product/1219/67648)；微信一次性授权语义参考 [腾讯云小程序订阅消息说明](https://cloud.tencent.com/document/product/1301/103770)。未知发送结果的保守策略是本项目的实现选择。

## 正式部署顺序与尚待完成的真实验收

1. 保持 `MINI_WECHAT_REMINDERS_ENABLED` 缺省或 `false`。确认目标数据库后，通过既有迁移工具执行 `089_mini_wechat_reminder_delivery.sql`；工具以真实 Neon transaction 执行全部语句。新授权 API 使用新增列，必须先迁移再部署代码。
2. 部署后端候选，配置正确的 `WECHAT_MINI_APP_ID`、`WECHAT_MINI_APP_SECRET`、`WECHAT_MINI_COMPANY_UPDATE_TEMPLATE_ID`、`WECHAT_MINI_PROGRAM_STATE` 和 `CRON_SECRET`；核对模板实际字段。只有 Bearer secret 有效，伪造 `x-vercel-cron` 标头无法触发发送。未开启发送时，客户端会显示提醒暂不可用。
3. 在隔离的体验数据库，指定一个测试微信账号，配置体验态模板跳转后开启消费者，完成“授权→新建待审核测试岗位→审核上线→微信收到→进入正确企业→取消/再次授权”的真机验证。不能直接用正式库存量订阅者进行测试；需要明确测试接收者才发送。
4. 真机通过后部署/开启正式消费者，并构建上传与正式环境一致的候选包，按 pending、failed、unknown 聚合和调度日志观察结果。微信提审/正式发布仍需按实际候选版本执行。

紧急停止时先关闭发送开关并重新部署使其生效，待当前在途请求结束；事件仍持久保留。无需回滚或删除用户关注数据。回退应用版本可保留新增列，但不要运行旧爬虫直接发送入口与新消费者两套逻辑。

本轮仅完成上述体验环境部署，没有发送真实通知，也没有执行正式环境迁移、付款、退款或账号注销操作。
