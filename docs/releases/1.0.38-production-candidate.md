## 本次部署问题与处理

最初本机预构建的 Vercel 包缺少 Linux sharp 依赖，曾导致部分 API 返回 500。正式域名先回退至旧基线以恢复服务；修复后改为云端构建，使用独立候选部署验证，再 promote。修复后实际部署 ID 见上表。

截图的开发目录同步故障来自 Preview 未开启 `MINI_ALLOW_CATALOG_IMPORT`。核验 Preview 和生产数据库主机不同后，仅修复 Preview 开关并重新部署；生产读取权威目录，不导入镜像数据。

## 构建与部署约定

`artifacts/releases/1.0.38/vercel-production-prebuilt.tar.gz` **不可再用于部署**，仅保留追溯；上传清单演练通过不能证明 Linux 原生模块可运行。发布清单已标记不可部署。

本轮使用 Vercel Linux 云端构建，`npm ci --include=optional`，`npm run build` 保留 TypeScript 检查。`vercel.json` 明确包含 Linux x64 sharp 和 libvips 文件。以后先执行：

```sh
npx vercel deploy --prod --skip-domain --yes
```

用新候选 URL 执行 `scripts/verify-mini-gateway.mjs --target=production --origin=<候选地址> --action=<只读 action> --vercel-curl`，检查图片和错误边界；通过后再 `vercel promote <已验证部署 ID> --yes`。切换前核对生产域名基线，避免覆盖其他版本。

上线后复测：

```sh
node scripts/test-mini-production-readonly.mjs --rounds=5 --output=tmp/mini-production-readonly.json
```
