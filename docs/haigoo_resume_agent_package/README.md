# Haigoo 个性化远程职业助手：Codex 实施包

本目录用于交给 Codex 审阅现有 Haigoo 网站代码库，并在不破坏现有业务的前提下，分阶段实现：

1. 用户上传简历与补充个人约束；
2. AI Skill 解析简历、识别核心优势与远程适配度；
3. 在必要时向用户提出高价值补充问题；
4. 用户确认结构化候选人画像；
5. Agent 查询 Haigoo 岗位数据库，完成硬性过滤、语义匹配与解释；
6. 用户确认目标岗位；
7. 系统基于事实证据和后台模板，为每个岗位生成定制简历；
8. 用户审核、导出并进入投递流程；
9. 用申请、面试与反馈数据持续优化画像和推荐。

## 文件说明

- `01_PRODUCT_TECH_PLAN.md`：完整产品与技术落地方案，包含用户流程、模块架构、数据库、AI 工作流、人工节点、隐私、评估与上线阶段。
- `02_CODEX_MASTER_PROMPT.md`：可直接复制给 Codex 的主实施 Prompt。
- `03_AGENTS.md`：建议放入项目仓库根目录的 Codex 协作说明模板。Codex 应先按真实技术栈补全，再开始大规模修改。
- `specs/REMOTE_CAREER_ASSESSMENT_SKILL.md`：简历评估与远程职业分析 Skill 的详细规范。
- `specs/DATA_CONTRACTS_AND_APIS.md`：结构化数据协议、状态机、数据库建议和 API 草案。

## 推荐使用顺序

1. 将本目录复制到代码仓库的 `docs/haigoo-career-agent/`。
2. 将 `03_AGENTS.md` 的内容合并进仓库根目录 `AGENTS.md`。
3. 向 Codex 提交 `02_CODEX_MASTER_PROMPT.md`。
4. 要求 Codex 先完成代码库审计、差异分析和实施计划，不要直接重写整个首页。
5. 采用功能开关和独立路由上线 MVP，再逐步替换首页主入口。

## 重要原则

- 不允许 AI 编造候选人的成果、数字、职责、语言能力或管理规模。
- 简历生成前必须经过候选人画像确认。
- 岗位匹配先执行地区、时区、语言、合同类型等硬性过滤，再计算软匹配。
- 首期不建议自动代替用户向第三方网站提交申请；先做到“生成、审核、导出、跳转、记录”。
- 原始简历、联系方式、家庭信息等属于敏感个人数据，不应进入普通日志或分析事件。
