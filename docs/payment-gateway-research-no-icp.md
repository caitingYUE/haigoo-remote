# 无 ICP 备案 + 海外服务器场景下的支付方案调研

> 评估日期：2026-08-07  
> 核心约束：Vercel 海外部署 + 无 ICP 备案 + 面向中国 C 端用户 + 企业主体（行渡科技）  
> 目标：Club 权益页会员支付（¥99 / ¥499 / ¥998）

---

## 一、核心约束分析

| 约束 | 影响 |
|------|------|
| **Vercel 海外服务器** | 无法部署在中国大陆境内，支付宝/微信官方直连要求服务器在国内或有 ICP 备案的域名 |
| **无 ICP 备案** | 支付宝/微信官方商户入驻要求网站完成 ICP 备案，未备案无法通过审核 |
| **面向中国 C 端** | 终端用户必须能用支付宝/微信支付，否则转化率极低 |
| **企业主体** | 行渡科技（杭州）有限责任公司，需合规收款、开票 |

> **根本矛盾**：国内支付（支付宝/微信直连）要求 ICP 备案，而项目无法备案。  
> **解决思路**：绕开「备案要求」的支付通道——要么走跨境/离岸架构，要么走不强制备案的聚合支付。

## 三、重点方案详解

### 方案 B（强烈推荐）：Airwallex 空中云汇

**为什么是最佳选择？**

| 维度 | 情况 |
|------|------|
| **商户主体** | ✅ 支持中国大陆企业主体（行渡科技可直接开户） |
| **终端支付** | ✅ 支持支付宝、微信支付、信用卡（Visa/MC/Amex）、银联、Apple Pay |
| **ICP 备案** | ❌ **不强制要求**（跨境收单架构，服务器在海外即可） |
| **费率** | ~1-1.5%（跨境收单，比 Stripe 低，比国内直连高） |
| **结算** | 支持结算到中国大陆银行账户（CNY），或 Airwallex 多币种账户 |
| **API** | 完善的开发者文档、REST API、SDK（支持 Node.js） |
| **合规** | ✅ 持有中国内地支付牌照 + 全球 87 项牌照，完全合规 |
| **税务** | 作为跨境收单，VAT/税务处理合规 |

**接入改造点：**
```
前端 (ProfileCenterPage.tsx)
  ├─ 选择方案 → POST /api/airwallex/checkout
  ├─ 跳转 Airwallex 托管支付页（或内嵌 Elements）
  └─ 支付成功跳回 successUrl

后端 (新增)
  ├─ POST /api/airwallex/checkout     → 创建 Payment Intent
  ├─ POST /api/airwallex/webhook      → 验签 + 处理支付成功事件
  ├─ 复用 paymentService.confirmPayment() 激活会员
  └─ 新增 airwallex-service.js
```

**注意事项：**
- Airwallex 对商户审核较严，需提供营业执照、法人信息、业务说明
- 费率需与销售确认（1-1.5% 为预估，实际取决于交易量和业务类型）
- 支付宝/微信通过 Airwallex 通道走，终端用户体验与直连基本一致

**适合度：⭐⭐⭐⭐⭐（企业主体 + 海外服务器 + 中国 C 端 + 合规，完美匹配）**

### 方案 A（备选推荐）：Stripe（香港离岸架构）

**核心机制**：Stripe 支持支付宝和微信支付作为终端支付方式，但中国大陆主体不能直接开户，需通过香港离岸架构。

| 维度 | 情况 |
|------|------|
| **商户主体** | ⚠️ 需香港公司/香港银行账户（行渡科技需注册香港子公司或用个人香港身份） |
| **终端支付** | ✅ 支付宝、微信支付、信用卡、Apple Pay、Google Pay |
| **ICP 备案** | ❌ 不需要（海外服务器 + 离岸架构） |
| **费率** | ~3.4% + HK$2.35（香港），跨境汇损另计 |
| **结算** | 结算到香港银行账户，再跨境汇回国内（或通过 Airwallex/万里汇中转） |
| **订阅支持** | ⚠️ 支付宝/微信的 recurring（自动续费）处于「受邀预览」阶段，暂不可用 |
| **API** | ✅ 业界最成熟的 API/SDK，TypeScript 原生支持 |
| **合规** | ✅ 合规，但 Stripe 未获中国大陆支付牌照，走离岸架构 |

**优势：**
- 技术集成体验业界最佳
- 支持支付宝 + 微信 + 信用卡，覆盖全
- 无需 ICP 备案

**劣势：**
- **需要香港主体**（注册香港公司成本约 ¥8000-15000/年维护）
- **资金回笼链路长**：Stripe → 香港银行 → 跨境汇款 → 国内银行，有汇损
- 费率比 Airwallex 高
- 支付宝/微信不支持自动续费（Club 会员若需自动续费则受限）

**适合度：⭐⭐⭐⭐（技术最优，但主体门槛和资金回笼是障碍）**

### 方案 C（快速但存风险）：聚合支付（PayJS / 虎皮椒）

| 平台 | 费率 | 企业支持 | 特点 | 风险 |
|------|------|----------|------|------|
| **PayJS** | 0.38%-0.6% | ✅ 微信服务商子商户号 | 技术文档好，T+1 结算 | 需自行处理投诉工单 |
| **虎皮椒** | 0.45% | ✅ 智能匹配营业执照 | 动态轮询商户池 | 夜间到账延迟，T+2 |
| **彩虹易支付** | 不详 | ⚠️ 高匿名 | 资金池对冲 | ⚠️ 合规风险高 |

**优势：**
- 费率低（0.38%-0.6%），接近直连
- 接入极快（标准 API，几小时上线）
- 不强制 ICP 备案
- 支持微信支付（部分支持支付宝）

**劣势/风险：**
- ⚠️ **合规灰度**：这些平台本质是「聚合支付服务商」，需核实背后持牌机构资质
- ⚠️ **资金安全**：非直连央行清算，资金经过第三方池子，有挪用/跑路风险
- ⚠️ **稳定性**：通道可能被封禁，夜间到账延迟
- ⚠️ **法律风险**：使用非备案支付接口可能面临行政处罚（有先例）
- 不适合月流水超 20 万的业务

**适合度：⭐⭐⭐（短期过渡可用，长期不推荐作为主支付通道）**

---

### 方案 D（受限）：支付宝当面付直连

| 维度 | 情况 |
|------|------|
| **终端支付** | ✅ 支付宝扫码 |
| **商户主体** | ✅ 中国企业（行渡科技） |
| **ICP 备案** | ⚠️ **通常需要**（网站支付场景要求备案域名） |
| **费率** | 0.6% |
| **可行性** | ❌ 因无 ICP 备案，大概率无法通过商户审核 |

> 当面付在「线下扫码」场景不强制备案，但「网站在线支付」场景需备案。项目是网站，故不适用。

## 四、决策建议

### 🏆 首选：方案 B - Airwallex 空中云汇

**理由：**
1. **唯一同时满足所有约束的方案**：中国企业主体 + 海外服务器 + 无 ICP 备案 + 支付宝/微信终端支付
2. **合规且有牌照**：Airwallex 持有中国内地支付牌照，无法律风险
3. **费率合理**：1-1.5%，远低于 Stripe（3.4%）和 Creem（3.9%+$0.4）
4. **资金回笼简单**：直接结算到国内银行账户（CNY），无需离岸架构
5. **API 成熟**：Node.js SDK，与现有技术栈契合

**下一步行动：**
1. 联系 Airwallex 销售，确认行渡科技开户资质和费率
2. 确认支付宝/微信支付方式在 Airwallex 通道的可用性
3. 确认是否支持固定价格的一次性支付（Club 会员非按次计费）
4. 开通后按上述改造点接入，复用现有 `payment_records` + `confirmPayment()`

### 🥈 备选：方案 A - Stripe（香港离岸架构）

若 Airwallex 审核不通过或费率不可接受，可考虑注册香港子公司走 Stripe。成本更高但技术体验最优，且未来出海可复用。

### ⚠️ 过渡方案：方案 C - PayJS

若急需上线且 Airwallex 审核周期长，可短期用 PayJS 过渡（费率低、接入快），但务必：
- 核实背后持牌机构资质（央行官网查询）
- 控制资金停留（及时提现）
- 月流水超 5 万后尽快切换到 Airwallex
